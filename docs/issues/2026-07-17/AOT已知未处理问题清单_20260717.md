**根因分析**：

### releaseDeadOperands 保守化与 bitset 重写（第十六轮）

**修复内容**：

1. **liveness_analysis.zig bitset 高性能重写**：
   - HashMap RegSet → 扁平 bitset 存储（live_in/live_out/inst_live_out 全部扁平化）
   - bitset 原语 `bitSet`/`bitUnset`/`bitIsSet`/`bitCopy`/`bitUnion`/`bitEquals`，全部 `inline`
   - 预分配一次大块，迭代工作集复用，零分配迭代
   - `successors_buf` 从 `[8]usize` 扩到 `[32]usize`，防 switch+exception_handler 溢出

2. **releaseDeadOperands 保守指令白名单**：
   - 仅释放安全指令操作数（BinaryOp/UnaryOp/CastOp/TypeCheckOp/InterpolateOp/BoxOp/UnboxOp/InstanceOfOp/SelectOp/PropertySetOp/ArrayKeyExistsOp/ClosureNewOp/ClosureBindOp/ImplementsInterfaceOp/StaticPropertySetOp/ChannelRecvOp）

3. **双重保护**：`isLiveAfter` + `isLiveAtBlockExit` 防止 liveness bug 误释放（任一为真则跳过）

4. **load mem2reg/ref_param 路径安全 retain**：先 retain 新值再 release 旧值（防 old==new use-after-free）

5. **setStaticVar/getStaticVar retain 修复**：setStaticVar 先 retain new 再 release old；getStaticVar retain 返回值

6. **php_array_iter_free 不再 release 对象迭代器**：由 releaseDeadOperands/cleanup 统一管理，防 double free

7. **.load 纳入 cleanup_regs**：load 结果纳入函数退出 cleanup 范围

**根因分析**：
- HashMap RegSet 性能差且内存碎片化 → bitset 重写
- releaseDeadOperands 对 call/store/load 等指令操作数释放 → use-after-free/double free → 保守白名单
- liveness PHI/loop back-edge 误判 → 双重保护
- load retain 顺序错误（release 旧→assign 新）→ old==new use-after-free → 调换为 retain 新→release 旧→assign
- setStaticVar 不 retain → 静态变量值悬垂 → retain 语义修复
- php_array_iter_free release 对象迭代器 → double free → 归一化管理

**测试结果**：全量 61/61 ALL PASS, DIFF=0, FAIL=0

**遗留问题**：

- call/store/load 等指令操作数不释放（保守策略），由 emitPreGcCleanup 补偿

### 状态机 releaseDeadOperands 启用与 PHI retain 顺序 + box/unbox 修复（第十八轮）

**修复内容**：

1. **PHI retain 顺序修复**：
   - `generatePhiValueAssignment` + `generatePhiAssignmentsParallel`（无依赖+有依赖路径）
   - 从 `release旧→assign→retain新` 改为 `retain新→release旧→assign`
   - 防 self-loop PHI（`x = phi(x from L)`）时 release 旧值使值被回收 → UAF

2. **box/unbox bitwise copy 修复**：
   - `releaseDeadOperands` 不再释放 box/unbox 操作数
   - box 是 bitwise copy（php_string→php_value），result 与操作数共享值，释放操作数使 result 悬垂
   - test_086 的 ternary 表达式 `reg_146 = box(reg_145)` 后释放 reg_145 → reg_146 悬垂 → 乱码输出

3. **状态机路径 releaseDeadOperands 启用**：
   - 在 `generateControlFlowStateMachine` 循环中设置 `current_gen_block_idx`/`current_gen_inst_idx`
   - 触发 `generateInstructionSimple` 内部的 `releaseDeadOperands`（line 12391）
   - 无需外部调用（否则双重释放）

**根因分析**：
- 第十七轮误判根因为 liveness PHI incoming 建模问题，实际根因有两层：
  1. PHI retain 顺序错误（`release旧→assign→retain新`，self-loop 时 UAF）
  2. box/unbox 在 releaseDeadOperands 中释放操作数（bitwise copy，result 悬垂）
- liveness PHI incoming 建模虽然不精确（过度保守），但不会导致误释放，非根因

**测试结果**：全量 61/61 ALL PASS, DIFF=0, FAIL=0

**遗留问题**：
- liveness PHI incoming 建模仍过度保守（所有前驱都认为所有 incoming 存活），性能次优但安全
- 后续可重构为 incoming 分别加到对应前驱的 `live_out`（提升释放精度）
- 详见变更文档：`docs/changes/2026-07-18/AOT状态机releaseDeadOperands启用与PHI_retain顺序修复_20260718.md`

### liveness PHI incoming 语义重构（第十九轮）

**修复内容**：

1. **`addUsedRegs` PHI 处理**：
   - PHI incoming 不再添加到 PHI block 的 `live_in`
   - PHI incoming 不在 PHI block 中“使用”，而在对应前驱块末尾“使用”

2. **`computeLiveOut` PHI incoming 精确添加**：
   - 计算前驱块 B 的 `live_out` 时，对于每个后继 S 的 PHI 节点
   - 仅添加 `inc.block == B` 的 incoming value 到 `live_out[B]`
   - 而非所有 incoming（修复前过度保守）

**根因分析**：
- 修复前所有前驱都认为所有 PHI incoming 存活 → releaseDeadOperands 无法释放非对应 incoming → ref_count 膨胀
- 修复后 incoming 精确归属到对应前驱 → 更精确的释放

**测试结果**：全量 61/61 ALL PASS, DIFF=0, FAIL=0

**遗留问题**：
- `releaseDeadOperands` 中 PHI 处理为死代码（PHI 指令被 `first_non_phi_idx` 过滤），后续可清理
- 详见变更文档：`docs/changes/2026-07-18/AOT_liveness_PHI_incoming语义重构_20260718.md`

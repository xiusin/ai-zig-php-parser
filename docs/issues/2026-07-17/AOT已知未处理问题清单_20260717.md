### P3-GC循环 详细说明

**尝试过程**：第十二轮将 `gcCollectCycles` 中的保守策略替换为 MarkGray → Scan → CollectWhite 三阶段完整循环检测算法。

**结果**：SEGV (exit 139)，程序在 `gc_collect_cycles()` 调用后崩溃。

**根因分析**：
1. AOT 生成的代码中，部分栈变量赋值路径未调用 `retain()`
2. MarkGray 递减所有内部引用的 ref_count 后，这些未 retain 的对象 ref_count 误判为 0
3. CollectWhite 阶段释放仍在栈上使用的对象 → SEGV（use-after-free）

**已保留的算法代码**（`runtime_lib_template.zig` ~line 979-1389）：

| 阶段 | 函数 | 作用 |
|------|------|------|
| MarkGray | `gcMarkGray`/`gcMarkGrayArray`/`gcMarkGrayObject`/`gcMarkGrayClosure` | 递减所有内部引用的 ref_count |
| Scan | `gcScan`/`gcScanArray`/`gcScanObject`/`gcScanClosure` | ref_count > 0 → black（存活），== 0 → white（垃圾） |
| ScanBlack | `gcScanBlackArray`/`gcScanBlackObject`/`gcScanBlackClosure` | 恢复 black 对象引用的子对象的 ref_count |
| CollectWhite | `gcCollectWhiteArray`/`gcCollectWhiteObject`/`gcCollectWhiteClosure` | 释放所有 white 对象 |

**启用方法**：将 `gcCollectCycles` 中保守策略的三行注释替换为三阶段调用：
```zig
// Phase 1: MarkGray
for (cycle_roots.items[0..batch_end]) |r| { gcMarkGray(r); }
// Phase 2: Scan
for (cycle_roots.items[0..batch_end]) |r| { gcScan(r); }
// Phase 3: CollectWhite (替换 if/else 中的 gcDestroy 调用)
```

**前置条件**：需先修复 AOT 代码生成中所有 `reg_X = reg_Y` 路径的 retain 缺失问题。

**修复内容**：

### releaseDeadOperands 精确化（第十五轮）

**修复内容**：

1. **liveness_analysis.zig 全面补全**：
   - `addUsedRegs` 从 13 种指令扩展到覆盖所有含寄存器操作数的指令类型（40+种）
   - 新增 `addTerminatorUsedRegs`：处理 `ret`/`cond_br`/`switch_`/`throw` 终止指令的操作数
   - `computeLiveOut` 新增 `exception_handler` 作为后继块（修复 try-catch 中寄存器被误释放）
   - `analyze` 和 `computeInstLiveness` 在处理指令前添加终止指令使用的寄存器

2. **native_linker.zig `releaseDeadOperands` 重写**：
   - 补全所有指令类型的 `used_regs` 收集（与 liveness analysis 同步）
   - 新增 `ref_ptr`/`this`/`ref_param_alloca` 跳过逻辑
   - 使用 `shouldReleaseReg` + `regMayHeap` 双重检查
   - 添加 null 检查避免双重 release

3. **单块函数路径启用 `releaseDeadOperands`**：
   - `generateInstructionSimple` 末尾自动调用（通过 `current_gen_block_idx`/`current_gen_inst_idx` 字段）
   - 单块函数路径设置字段启用 release
   - 状态机路径和结构化路径暂不启用（PHI/loop back-edge 需更精确的 liveness）

4. **load 代码生成 retain 修复**：
   - mem2reg 路径：添加 `release` 旧值 + `retain` 新值
   - ref_param_alloca 路径：同上
   - 原 load 路径已有 retain（确认无问题）

5. **`setStaticVar`/`getStaticVar` retain 修复**：
   - `setStaticVar`：retain 新值并 release 旧值
   - `getStaticVar`：retain 返回值

6. **`.load` 纳入 `cleanup_regs`**：load 结果纳入函数退出 cleanup 范围

**根因分析**：
- liveness analysis 缺失 ~30 种指令类型 → 误判死亡 → use-after-free
- liveness analysis 未处理终止指令操作数 → 返回值被释放 → 函数返回 null
- liveness analysis 未处理异常处理器 → catch 块使用的寄存器被释放 → SEGV
- `load` mem2reg 路径不 retain → releaseDeadOperands 释放后 alloca 悬垂
- `setStaticVar` 不 retain → 静态变量值被释放后悬垂指针

**测试结果**：全量 61/61 ALL PASS, DIFF=0, FAIL=0

**遗留问题**：
- 状态机路径和结构化控制流路径暂未启用 `releaseDeadOperands`（PHI/loop back-edge 场景 liveness 需更精确）
- `emitPreGcCleanup` 保留作为未覆盖路径的补充
- 后续可通过更精确的 liveness analysis（处理 PHI 节点在状态机中的特殊语义）逐步启用

## 一、高层摘要

### 核心发现

| 指标 | 数值 | 说明 |
|------|------|------|
| 重复/冗余代码总量 | ~89,000 行 | 占项目总量 31% |

| **潜在死代码** | **41,654 行** | runtime/ 目录中未被入口文件引用的文件 |

### 最严重问题

## 二、审查方法论

### 审查维度

1. **文件级**：同名文件、同功能文件的跨目录重复
2. **类型级**：核心类型（Value、PHPArray、PHPString）的多处定义
3. **函数级**：`pub fn` 签名级别的重复（通过 `comm` 交叉比对）
4. **常量级**：NaN Boxing 编码常量的值一致性
5. **依赖图级**：通过 `build.zig` 和 `@import` 链追踪死代码

### 审查工具

- `wc -l`：文件规模量化
- `diff`：文件内容差异比对
- `comm -12`：函数签名集合交集（重复量化）
- `grep -rl`：反向依赖追踪
- `build.zig` 分析：编译入口确认

### 依赖追踪路径

```
build.zig
  └→ src/main.zig
       └→ src/runtime/mod.zig （43 个 @import）
       └→ src/aot/root.zig
            └→ src/aot/runtime_lib.zig （3,367 行版，编译器内部用）
       └→ src/aot/native_linker.zig
            └→ 复制 runtime_lib_template.zig → AOT产物/runtime_lib.zig
            └→ 复制 rt_*.zig → AOT产物/ （但无文件导入它们）
```

## 三、重复实现详细分析

### 3.1 [P0-致命] AOT 运行时类型系统：26,880 行完全死代码

#### 问题描述

`native_linker.zig` 在 AOT 编译时执行以下操作：

1. 将 `src/aot/runtime_lib_template.zig`（30,181 行）复制为 AOT 编译目录中的 `runtime_lib.zig`
2. 同时将 `rt_*.zig` 文件群（共 10 个文件，26,880 行）复制到同一目录
3. 生成的 AOT 主文件通过 `const runtime = @import("runtime_lib.zig")` 导入模板
4. **但 `runtime_lib_template.zig` 不导入任何 `rt_*.zig` 文件**
5. **生成的 AOT 主文件也不导入任何 `rt_*.zig` 文件**

结论：`rt_*.zig` 文件被复制到编译目录但从未被导入，是 **100% 死代码**。

#### 证据

**native_linker.zig 第 18534-18552 行**（文件复制列表）：
```zig
fn copyOtherRuntimeFiles(self: *Self, temp_dir: []const u8, base_path: []const u8) !void {
    const files = [_]struct { src: []const u8, dst: []const u8 }{
        // ...
        .{ .src = "src/aot/rt_core.zig", .dst = "rt_core.zig" },
        .{ .src = "src/aot/rt_runtime.zig", .dst = "rt_runtime.zig" },
        .{ .src = "src/aot/rt_string.zig", .dst = "rt_string.zig" },
        .{ .src = "src/aot/rt_array.zig", .dst = "rt_array.zig" },
        .{ .src = "src/aot/rt_value.zig", .dst = "rt_value.zig" },
        .{ .src = "src/aot/rt_io.zig", .dst = "rt_io.zig" },
        .{ .src = "src/aot/rt_funcs1.zig", .dst = "rt_funcs1.zig" },
        .{ .src = "src/aot/rt_class.zig", .dst = "rt_class.zig" },
        .{ .src = "src/aot/rt_funcs2.zig", .dst = "rt_funcs2.zig" },
        .{ .src = "src/aot/rt_funcs3.zig", .dst = "rt_funcs3.zig" },
    };
```

**runtime_lib_template.zig 的导入列表**（不包含任何 rt_* 文件）：
```zig
const concurrency = @import("concurrency_runtime.zig");
const array_ops_shared = @import("array_ops_shared.zig");
const nanbox_abi = @import("nanbox_abi.zig");
pub const profiler = @import("profiler.zig");
pub const flamegraph = @import("flamegraph.zig");
pub const pprof = @import("pprof.zig");
// 没有 @import("rt_array.zig") 等
```

**生成的 AOT 主文件**（native_linker.zig 第 686-690 行）：
```zig
\\// Generated by zig-php AOT compiler
\\const std = @import("std");
\\const runtime = @import("runtime_lib.zig");
// 没有导入 rt_*.zig
```

#### 函数级重复量化

| rt_*.zig 文件 | 行数 | pub fn 数 | 与 template 重复数 | 独有函数数 | 重复率 |
|--------------|------|----------|------------------|-----------|--------|
| `rt_funcs1.zig` | 5,676 | 159 | 159 | **0** | **100%** |
| `rt_funcs2.zig` | 7,032 | 235 | 217 | **0** | **100%** |
| `rt_funcs3.zig` | 1,448 | 32 | 32 | **0** | **100%** |
| `rt_runtime.zig` | 1,348 | 17 | 11 | 6 | 65% |
| `rt_io.zig` | 1,761 | 63 | 61 | 2 | 97% |
| `rt_class.zig` | 7,533 | 92 | 69 | 23 | 75% |
| `rt_array.zig` | 447 | 33 | 18 | 15 | 55% |
| `rt_value.zig` | 1,345 | 61 | 25 | 36 | 41% |
| `rt_string.zig` | 277 | 8 | 7 | 1 | 88% |
| `rt_core.zig` | 13 | 0 | 0 | 0 | N/A |
| **合计** | **26,880** | **700** | **599** | **83** | **86%** |

> 注：rt_*.zig 中"独有"的函数（83 个）实际上也在 template 中以不同名称或内联方式存在。即使假设它们确实独有，这些函数也从未被调用（因为 rt_*.zig 本身就是死代码）。

#### 类型定义重复

| 类型 | rt_*.zig 中的定义 | template 中的定义 | 实现差异 |
|------|------------------|------------------|---------|
| `Value` | `rt_value.zig:19` (struct{val: u64}) | `template:2209` (struct{val: u64}) | NaN boxing 常量相同，函数体高度相似 |
| `PHPArray` | `rt_array.zig:72` (Elements-based) | `template:1738` (Elements-based) | 字段结构相同 |
| `PHPString` | `rt_string.zig:12` (data/length/ref_count) | `template:1405` (data/length/ref_count) | 字段结构相同，277行 vs 266行 |

#### 根因分析

`rt_*.zig` 文件的注释说明：`// 拆分文件（用于降低编译内存峰值）`。这是一次将 30,181 行的 `runtime_lib_template.zig` 拆分为多个小文件的尝试。但拆分过程中：

1. 创建了 `rt_*.zig` 文件，将 template 中的代码复制过去
2. **没有从 template 中删除已搬出的代码**
3. **没有在 template 中添加对 `rt_*.zig` 的 `@import`**
4. 拆分工作未完成，但文件已留在代码库中

### 3.2 [P0-严重] 两套不兼容的 runtime_lib.zig

#### 问题描述

项目中存在两个名为 `runtime_lib.zig` 的文件，但它们的实现**完全不同**：

| 属性 | `src/aot/runtime_lib.zig` | `src/aot/runtime_lib_template.zig` |
|------|--------------------------|-----------------------------------|
| 行数 | 3,367 | 30,181 |
| 值类型 | `PHPValue`（extern struct，tagged union） | `Value`（struct{val: u64}，NaN boxing） |
| 数组实现 | Hash bucket + linked list | Elements（packed_values + mixed ArrayHashMap） |
| 字符串实现 | `PHPString`（data/length/ref_count/encoding） | `PHPString`（data/length/ref_count/is_static） |
| 使用场景 | 编译器内部（`aot/root.zig` 导入） | AOT 编译产物（被复制为 `runtime_lib.zig`） |
| GC 方式 | 无内置 GC | 引用计数 + COW |

#### 证据

**runtime_lib.zig（3,367 行版）的值类型**：
```zig
pub const ValueTag = enum(u8) { null = 0, bool = 1, int = 2, float = 3, ... };
pub const ValueData = extern union {
    bool_val: bool, int_val: i64, float_val: f64,
    string_ptr: ?*PHPString, array_ptr: ?*PHPArray, ...
};
pub const PHPValue = extern struct {
    tag: ValueTag,
    data: ValueData,
};
pub const Value = PHPValue;
```

**runtime_lib_template.zig（30,181 行版）的值类型**：
```zig
pub const Value = struct {
    val: u64,  // NaN boxing
    pub const SIGN_BIT: u64 = nanbox_abi.SIGN_BIT;
    pub const QNAN: u64 = nanbox_abi.QNAN;
    // ...
};
```

**runtime_lib.zig（3,367 行版）的 PHPArray**：
```zig
pub const PHPArray = struct {
    allocator: Allocator,
    buckets: []?*ArrayEntry,    // Hash bucket 数组
    bucket_count: usize,
    entry_count: usize,
    first: ?*ArrayEntry,        // 链表头
    last: ?*ArrayEntry,         // 链表尾
    next_int_key: i64,
    ref_count: u32,
};
```

**runtime_lib_template.zig 的 PHPArray**：
```zig
pub const PHPArray = struct {
    elements: Elements,          // Elements 结构体
    next_index: i64,
    ref_count: usize,
    gc_info: GCInfo,
    has_active_refs: bool = false,
    ref_lock_count: u32 = 0,
};
```

#### 影响

- 修改 AOT 运行时行为时，开发者可能修改了 `runtime_lib.zig`（3,367 行版），但实际 AOT 产物使用的是 `runtime_lib_template.zig`（30,181 行版），导致修改无效
- 两套 PHPArray 的内存布局完全不同，如果编译器内部代码（引用 3,367 行版）和 AOT 产物代码（引用 30,181 行版）需要交互，会导致内存损坏

### 3.3 [P0-严重] NaN Boxing ABI 常量冲突

#### 问题描述

| 文件 | 行数 | TYPE_REF 值 | TYPE_BIGINT | TYPE_RESOURCE |
|------|------|------------|-------------|---------------|
| `src/shared/nanbox_abi.zig` | 43 | `0x0003000000000000` | **未定义** | **未定义** |
| `src/aot/nanbox_abi.zig` | 38 | `0x0002800000000000` | `0x0003000000000000` | `0x0003800000000000` |
| `src/runtime/nan_boxing.zig` | 109 | N/A（完全不同编码方案） | N/A | N/A |

#### 证据

**shared/nanbox_abi.zig**：
```zig
pub const TYPE_REF: u64 = 0x0003000000000000;
// 没有 TYPE_BIGINT 和 TYPE_RESOURCE
```

**aot/nanbox_abi.zig**：
```zig
pub const TYPE_REF: u64 = 0x0002800000000000; // 修复：使用未占用的类型码
pub const TYPE_BIGINT: u64 = 0x0003000000000000; // 堆装箱的大整数
pub const TYPE_RESOURCE: u64 = 0x0003800000000000; // 资源类型
```

**关键冲突**：`shared/nanbox_abi.zig` 中 `TYPE_REF = 0x0003...`，而 `aot/nanbox_abi.zig` 中 `TYPE_BIGINT = 0x0003...`。如果两个模块的值需要交互，引用类型和大整数类型的编码会冲突。

#### build.zig 中的模块定义

```zig
const nanbox_abi_mod = b.createModule(.{
    .root_source_file = b.path("src/shared/nanbox_abi.zig"),  // 使用 shared 版本
});
runtime_mod.addImport("nanbox_abi", nanbox_abi_mod);  // runtime 使用 shared 版本
```

AOT 编译产物使用的是 `aot/nanbox_abi.zig`（通过文件复制），而编译器内部通过 `build.zig` 使用的是 `shared/nanbox_abi.zig`。

### 3.4 [P0-严重] 值类型系统五重实现

#### 问题描述

| # | 文件 | 行数 | 类型名 | 编码方式 | 使用场景 |
|---|------|------|--------|---------|---------|
| 1 | `src/runtime/types.zig` | 4,535 | `Value` | tagged union | 解释器主类型 |
| 2 | `src/aot/rt_value.zig` | 1,345 | `Value` | NaN boxing | AOT 死代码（见 3.1） |
| 3 | `src/aot/runtime_lib_template.zig` | 30,181 | `Value` | NaN boxing | AOT 产物运行时 |
| 4 | `src/runtime/fast_value.zig` | 644 | `FastValue` | 独立编码 | 运行时优化路径 |
| 5 | `src/runtime/nan_boxing.zig` | 109 | `Value` | packed struct | 运行时（不同编码方案） |
| 6 | `src/aot/runtime_lib.zig` | 3,367 | `PHPValue`/`Value` | extern struct + tagged union | AOT 编译器内部 |
| 7 | `src/runtime/value_array.zig` | 628 | - | 数组值存储 | 运行时 |

#### 编码方案差异

```
方案 A (runtime/types.zig):
  Value = union(enum) { null, bool, int(i64), float(f64), string(*PHPString), ... }
  → Zig 原生 tagged union，32+ 字节

方案 B (aot/runtime_lib_template.zig + rt_value.zig):
  Value = struct { val: u64 }
  → NaN boxing，8 字节，指针通过 TAG_PTR | TYPE_TAG | ADDR 编码

方案 C (runtime/nan_boxing.zig):
  Value = packed struct { bits: u64 }
  → 不同的 NaN boxing 编码（TAG_MASK=0xFFFF_0000...，与方案 B 不兼容）

方案 D (aot/runtime_lib.zig):
  PHPValue = extern struct { tag: u8, data: extern union { ... } }
  → C 兼容布局，16+ 字节

方案 E (runtime/fast_value.zig):
  FastValue = 独立优化编码
```

#### 影响

- 值类型转换代码散布在各引擎中，无法共享
- 修改值类型语义时需要同步 5+ 处定义
- `nan_boxing.zig`（方案 C）的编码方案与 AOT 的 `nanbox_abi.zig`（方案 B）完全不兼容

### 3.7 [P1-中等] runtime/ 目录 41,654 行潜在死代码

#### 问题描述

`src/runtime/` 目录包含 165 个 Zig 文件。通过追踪 `runtime/mod.zig` 和 `runtime/root.zig` 的 `@import` 链，发现 73 个文件未被任何入口文件直接引用。

但这些文件可能被其他 runtime 文件间接引用（如 `gc.zig` 引用 `generational_gc.zig`）。排除确认被间接引用的文件后，仍有约 30 个文件完全无引用。

#### 完全无引用的文件（抽样确认）

| 文件 | 行数 | 被引用情况 |
|------|------|-----------|
| `packed_array.zig` | 1,199 | ❌ 无引用 |
| `bigdecimal.zig` | 771 | ❌ 无引用 |
| `cow.zig` | 843 | ❌ 无引用 |
| `benchmark_fast_value.zig` | 404 | ❌ 无引用 |
| `benchmark_fast_vm.zig` | 522 | ❌ 无引用 |
| `async_io_windows.zig` | 474 | ❌ 无引用（Windows 平台） |
| `cookie.zig` | 19 | ❌ 无引用 |
| `simd.zig` | 98 | ❌ 无引用 |

## 四、优化方案

### 方案 1：立即清理（零风险，预计节省 27,500+ 行）

| 步骤 | 操作 | 节省行数 | 风险 |
|------|------|---------|------|
| 1.1 | 删除 6 个 vim 交换文件 + `native_linker.zig.backup2` | 672 KB | 零 |
| 1.2 | 统一 `time_compat.zig`：删除 `runtime/` 和 `bytecode/` 版本，全部使用 `shared/` 版本 | 120 | 零 |
| 1.3 | 删除 `type_inference_pass_old.zig`（确认新版已替代） | 187 | 零 |
| 1.4 | 删除 `ownership_tracker.zig`（确认 v2 已替代） | 75 | 零 |
| 1.5 | 删除 `gc/generational_gc.zig`（确认 runtime 版本已替代） | 133 | 零 |
| 1.6 | **删除 `rt_*.zig` 文件群**（确认是死代码） + 修改 `native_linker.zig` 移除复制逻辑 | 26,880 | **需验证** |

**验证方法**：删除后执行 `timeout 120 zig build` + `timeout 10 zig build test` + AOT 模糊测试。

### 方案 2：nanbox_abi 常量统一（低风险）

| 步骤 | 操作 | 风险 |
|------|------|------|
| 2.1 | 将 `aot/nanbox_abi.zig` 中的 TYPE_BIGINT 和 TYPE_RESOURCE 添加到 `shared/nanbox_abi.zig` | 零 |
| 2.2 | 统一 TYPE_REF 为 `0x0002800000000000`（AOT 版本的值，因为 AOT 产物已使用此值） | 需确认 runtime 不通过 TYPE_REF 编码引用 |
| 2.3 | 删除 `aot/nanbox_abi.zig`，AOT 编译产物改用 `shared/nanbox_abi.zig` | 需修改 native_linker 复制列表 |
| 2.4 | 评估 `runtime/nan_boxing.zig` 是否可删除（编码方案完全不同，疑似废弃实验） | 需确认无引用 |

### 方案 3：runtime_lib 命名澄清（中等风险）

| 步骤 | 操作 | 风险 |
|------|------|------|
| 3.1 | 将 `src/aot/runtime_lib.zig`（3,367行）重命名为 `src/aot/compiler_runtime_lib.zig` | 需更新所有引用 |
| 3.2 | 将 `src/aot/runtime_lib_template.zig`（30,181行）重命名为 `src/aot/aot_runtime_lib.zig` | 需更新 native_linker |
| 3.3 | 评估 `compiler_runtime_lib.zig`（3,367行）是否仍在使用，如否可删除 | 需确认 |

### 方案 4：AOT 运行时真正拆分（高风险，长期）

将 `runtime_lib_template.zig`（30,181 行）拆分为独立模块，消除超大文件：

```
runtime_lib_template.zig (30,181行)
  → types.zig         (Value, PHPArray, PHPString, PHPObject 定义)
  → array_ops.zig     (数组操作函数)
  → string_ops.zig    (字符串操作函数)
  → value_ops.zig     (值操作函数：比较、运算、转换)
  → io_ops.zig        (IO 函数)
  → class_runtime.zig (类运行时)
  → builtin_funcs.zig (PHP 内置函数)
  → gc_runtime.zig    (GC 运行时)
```

每个拆分文件通过 `@import("types.zig")` 引用类型，模板文件通过 `@import` 聚合所有模块。

### 方案 5：runtime/ 死代码清理（中等风险）

| 步骤 | 操作 | 预计节省 |
|------|------|---------|
| 5.1 | 对 73 个未被入口文件引用的文件做深度引用分析 | - |
| 5.2 | 删除确认完全无引用的文件（约 30 个，~11,000 行） | ~11,000 |
| 5.3 | 对有间接引用但功能可疑的文件标记 `@deprecated` | - |

### 方案 6：内置函数共享层（极高风险，超长期）

设计一个 trait/接口层，让三套引擎共享内置函数的语义实现：

```zig
// shared/builtin_functions.zig
pub fn array_push(arr: anytype, value: anytype) !usize {
    // 统一的语义实现，通过 anytype 适配不同引擎的值类型
}
```

此方案需要统一值类型系统或设计适配层，工程量极大。

## 七、后续建议

### 7.1 建立 CI 重复检测

在 CI 流水线中加入以下检查：
1. **文件名重复检测**：禁止同名文件出现在不同目录
2. **函数签名重复检测**：对 `pub fn` 做去重检查
3. **死代码检测**：使用 `zig build-obj --analyze` 或自定义脚本检测未被引用的文件
4. **临时文件检测**：禁止 `.*!*`、`*.backup*`、`*_old*`、`*_v2*` 文件提交

### 7.2 建立架构边界规范

```
src/
  shared/          ← 跨引擎共享层（值类型定义、ABI 常量、工具函数）
    nanbox_abi.zig
    time_compat.zig
    builtin_functions.zig (未来)
  compiler/        ← 编译器层（词法/语法分析、AST）
  aot/             ← AOT 引擎专属
    aot_runtime/   ← AOT 运行时（从 template 拆分）
  runtime/         ← 解释器引擎专属
  bytecode/        ← 字节码引擎专属
  jit/             ← JIT 引擎专属
```

### 7.3 制定文件命名规范

- 禁止 `_old`、`_v2`、`.backup` 后缀
- 旧版本通过 Git 分支管理，不留在主分支
- 备份文件使用 `git stash` 或 `git tag`
- 新版本替换旧版本时，必须在同一 commit 中删除旧文件

### 7.4 AOT 运行时重构路线图

1. **Phase 1**（1 周）：删除 `rt_*.zig` 死代码，清理临时文件
2. **Phase 2**（2 周）：统一 `nanbox_abi`，澄清 `runtime_lib` 命名
3. **Phase 3**（1 个月）：将 `runtime_lib_template.zig` 拆分为独立模块
4. **Phase 4**（3 个月）：设计内置函数共享层，逐步统一三套引擎的函数实现

### 7.5 定期审计

- 每月执行一次重复检测脚本
- 每次大功能合并前检查是否有重复实现
- 使用 `wc -l` + `comm` 组合做快速重复扫描

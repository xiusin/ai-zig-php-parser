> 扫描日期：2026-07-16

## 一、高层摘要 (TL;DR)

系统存在 **22 类重复实现**，涉及约 **89,000 行**重复或高度冗余代码（占总量的 31%）。其中 **P0 级（严重）** 6 项，**P1 级（中等）** 10 项，**P2 级（低）** 6 项。核心问题集中在：

1. AOT 运行时类型系统三重定义（`runtime_lib.zig` / `runtime_lib_template.zig` / `rt_*.zig`）
2. 值类型系统五重实现（`types.zig` / `rt_value.zig` / `runtime_lib_template.zig` / `fast_value.zig` / `nan_boxing.zig`）
3. GC 实现 14 处分散（总 9,775 行）
4. 数组/字符串操作各 7 处实现
5. 新旧版本文件未清理（`_old` / `_v2` / `.backup2` / vim 交换文件）

### 3.1 [P0] AOT 运行时类型系统三重定义

**重复文件：**

| 文件 | 行数 | 定义的类型 | 角色 |
|------|------|-----------|------|
| `src/aot/runtime_lib.zig` | 3,367 | PHPValue, PHPArray, PHPString, PHPObject | 编译器内部引用的运行时库 |
| `src/aot/runtime_lib_template.zig` | 30,181 | Value, PHPArray, PHPString, PHPObject | AOT 编译产物模板（被复制为 `runtime_lib.zig`） |
| `src/aot/rt_array.zig` | 447 | PHPArray（重复定义） | 拆分文件 |
| `src/aot/rt_value.zig` | 1,345 | Value（重复定义） | 拆分文件 |
| `src/aot/rt_string.zig` | 277 | PHPString（重复定义） | 拆分文件 |
| `src/aot/rt_runtime.zig` | 1,348 | 运行时函数 | 拆分文件 |
| `src/aot/rt_io.zig` | 1,761 | IO 函数 | 拆分文件 |
| `src/aot/rt_class.zig` | 7,533 | 类运行时 | 拆分文件 |
| `src/aot/rt_core.zig` | 13 | 核心入口 | 拆分文件 |
| `src/aot/rt_funcs1.zig` | 5,676 | 内置函数 1 | 拆分文件 |
| `src/aot/rt_funcs2.zig` | 7,032 | 内置函数 2 | 拆分文件 |
| `src/aot/rt_funcs3.zig` | 1,448 | 内置函数 3 | 拆分文件 |

**问题描述：**

`native_linker.zig` 在 AOT 编译时执行以下操作：
1. 将 `runtime_lib_template.zig`（30,181 行）复制为编译目录中的 `runtime_lib.zig`
2. 同时将 `rt_*.zig`（共 26,880 行）复制到同一编译目录
3. `rt_*.zig` 文件通过 `@import("runtime_lib.zig")` 导入模板中的类型
4. **但 `rt_array.zig`、`rt_value.zig`、`rt_string.zig` 又各自重新定义了 `PHPArray`、`Value`、`PHPString`**

**函数级重复确认：**

`rt_array.zig` 中的 PHPArray（33 个方法）与 `runtime_lib_template.zig` 中的 PHPArray（32 个方法）有 **18 个完全同名方法**：`clone`, `count`, `deinit`, `eql`, `get`, `has`, `hash`, `init`, `iterator`, `next`, `ordered`, `push`, `put`, `release`, `remove`, `retain`, `set`, `unset`

`rt_value.zig` 中的 Value（61 个函数）与 `runtime_lib_template.zig` 中的 Value（40 个函数）有 **25 个完全同名函数**

`rt_string.zig` 中的 PHPString（266 行）与 `runtime_lib_template.zig` 中的 PHPString（266 行）**行数完全相同**，有 7 个同名方法

**影响：**
- 同一类型在编译产物中存在两份定义，维护时必须同步修改
- `runtime_lib.zig`（3,367 行）与 `runtime_lib_template.zig`（30,181 行）是**完全不同的实现**，但同名，极易混淆
- AOT 编译器内部引用 `runtime_lib.zig`（3,367 行版本），AOT 产物使用 `runtime_lib_template.zig`（30,181 行版本），两者 API 不一致

### 3.2 [P0] 值类型系统五重实现

**重复文件：**

| 文件 | 行数 | 类型名 | 编码方式 | 所属引擎 |
|------|------|--------|---------|---------|
| `src/runtime/types.zig` | 4,535 | Value | tagged union | 解释器 |
| `src/aot/rt_value.zig` | 1,345 | Value | NaN boxing | AOT（拆分版） |
| `src/aot/runtime_lib_template.zig` | 30,181 | Value | NaN boxing | AOT（模板版） |
| `src/runtime/fast_value.zig` | 644 | FastValue | 独立编码 | 优化路径 |
| `src/runtime/nan_boxing.zig` | 109 | Value | packed struct | 运行时（不同编码） |
| `src/runtime/value_array.zig` | 628 | - | 数组值 | 运行时 |
| `src/runtime/benchmark_fast_value.zig` | 404 | - | 基准测试 | benchmark |

**问题描述：**

系统存在至少 3 种不同的值编码方案：
1. **Tagged Union**（`runtime/types.zig`）：Zig 原生 union(enum)，用于解释器
2. **NaN Boxing v1**（`aot/rt_value.zig` + `runtime_lib_template.zig`）：64 位编码，指针通过 TAG_PTR 编码
3. **NaN Boxing v2**（`runtime/nan_boxing.zig`）：完全不同的位模式（TAG_MASK=0xFFFF_0000...）
4. **FastValue**（`runtime/fast_value.zig`）：另一种优化编码

**影响：**
- 值类型转换代码散布在各引擎中，无法共享
- 修改值类型语义时需要同步 5+ 处定义
- `nan_boxing.zig` 的编码方案与 AOT 的 `nanbox_abi.zig` 完全不兼容

### 3.3 [P0] NaN Boxing ABI 三处定义且常量冲突

| 文件 | 行数 | TYPE_REF 值 | 说明 |
|------|------|------------|------|
| `src/shared/nanbox_abi.zig` | 43 | `0x0003000000000000` | 共享模块 |
| `src/aot/nanbox_abi.zig` | 38 | `0x0002800000000000` | AOT 模块（**值不同！**） |
| `src/runtime/nan_boxing.zig` | 109 | N/A（不同方案） | 运行时（完全不同的编码） |

**关键问题：** `shared/nanbox_abi.zig` 和 `aot/nanbox_abi.zig` 的 `TYPE_REF` 常量值**不同**（`0x0003...` vs `0x0002...`），但 AOT 模块的 `rt_value.zig` 导入的是 AOT 版本。如果运行时和 AOT 之间需要传递值，会导致类型标签解析错误。

## 四、重复根因分析

### 4.1 架构分裂

系统存在三套独立的执行引擎（解释器、字节码 VM、AOT 编译器），各自实现了：
- 值类型系统
- 内置函数库
- 优化器
- 寄存器分配器
- 类型推导

这导致几乎所有核心功能都有 3 份实现。

### 4.2 AOT 运行时拆分不彻底

`runtime_lib_template.zig`（30,181 行）是一个超大单文件，被拆分为 `rt_*.zig` 文件群（26,880 行）。但拆分时**没有从原文件中移除已拆出的代码**，导致同一类型定义同时存在于模板和拆分文件中。

### 4.3 演进过程中未清理旧版本

多个功能在迭代中产生了新版本（`_v2`、`_old` 后缀），但旧版本未被删除：
- `ownership_tracker.zig` vs `ownership_tracker_v2.zig`
- `type_inference_pass.zig` vs `type_inference_pass_old.zig`
- `runtime/generational_gc.zig` vs `gc/generational_gc.zig`

### 4.4 优化路径并行开发

`runtime/` 目录中存在大量并行优化实现（`fast_*`、`simd_*`、`packed_*`），这些可能是不同时期的性能优化尝试，但都保留在代码库中。

## 六、复测路径

1. 删除临时文件后执行 `timeout 120 zig build` 确认编译通过
2. 每次合并/删除文件后执行 `timeout 10 zig build test` 确认测试通过
3. AOT 功能验证：`timeout 10 ./aot_compile_test` 执行模糊测试脚本

## 七、后续开发建议

1. **建立架构边界规范**：明确三套引擎（解释器/字节码/AOT）的共享层与专属层，禁止在专属层重复实现共享层已有的功能
2. **引入重复检测 CI**：在 CI 中加入函数签名级别的重复检测，防止新增重复
3. **制定文件命名规范**：禁止 `_old`/`_v2`/`.backup` 后缀，旧版本必须通过 Git 分支管理
4. **AOT 运行时重构**：将 `runtime_lib_template.zig` 彻底拆分为独立的类型/函数模块，消除与 `rt_*.zig` 的重复定义
5. **共享内置函数层**：设计一个 trait/接口层，让三套引擎共享内置函数的语义实现，仅在调用约定层面适配

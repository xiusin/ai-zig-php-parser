# AOT 编译器性能优化总结

## 🎯 目标与成果
- **目标**: ≤15x 慢于 PHP-CLI
- **当前**: 10.1ms vs 1.0ms = **10.0x 慢** ✅
- **提升**: 从 15.0x → 10.0x（提升 33%）

## ✅ 已实施优化

### 1. comptime @Vector SIMD 数组求和
- **文件**: `src/aot/runtime_lib_template.zig:5798`
- **技术**: 自动选择最优向量宽度（AVX2/AVX512）
- **效果**: 纯整数数组 3-5x 提升

### 2. 静态字符串池
- **文件**: `src/aot/native_linker.zig:255-275`
- **技术**: 运行时初始化一次，避免重复 HashMap 查找
- **效果**: 字面量字符串零 GC 压力

### 3. comptime 查找表（已有）
- **文件**: `src/aot/runtime_lib_template.zig:2972-2987`
- **技术**: strtoupper/strtolower 使用 256 字节查找表
- **效果**: 零分支，单次查表

### 4. LICM 优化顺序调整
- **文件**: `src/aot/optimizer.zig:730-790`
- **修改**: LICM 在循环展开之前执行
- **状态**: 部分生效（需进一步调试）

## 🔴 待优化项

### 1. 字符串拼接（800x 慢）
- **根因**: 循环内重复 concat + 分配
- **方案**: LICM 提升常量 concat 到循环外
- **预期**: 800x → 5x

### 2. 数组求和（15.3x 慢）
- **根因**: 循环内重复调用 array_sum
- **方案**: LICM 提升纯函数调用
- **预期**: 15.3x → 2x

### 3. LICM 完全生效
- **问题**: load + call 依赖分析不完整
- **方案**: 改进 isInvariantForPureCall 逻辑
- **或**: 代码生成层面检测并优化

## 🎓 经验教训

1. **Zig comptime 强大**: @Vector SIMD 自动选择最优宽度
2. **优化顺序重要**: LICM 必须在展开之前
3. **IR 层优化难**: 依赖分析复杂，考虑代码生成层优化
4. **Runtime 优化有效**: 查找表、SIMD 等直接提升性能

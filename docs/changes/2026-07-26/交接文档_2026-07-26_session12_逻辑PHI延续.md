## 三、`||`/`&&` PHI 未完全修复的原因

### `isPrime` 的问题
```php
if ($n < 2) return false;       // Block 0: cond_br
if ($n < 4) return true;        // Block else1: cond_br → then2 / else2
if ($n % 2 === 0 || $n % 3 === 0) return false;  // Block else2: || cond_br
for ($i = 5; ...) { ... }       // Block if_merge: for loop
```

**处理流程**：
1. Block 0 的 cond_br case 处理 → 生成 if/else
2. else1 的 cond_br 在 else 分支中递归处理
3. 递归调用处理 then2 (return true) → `return_generated = true`
4. **递归调用的 early-exit 将 else2、logical_rhs、logical_merge、if_then 全部标记为已处理**
5. `if_then_` 被跳过 → `generateIfFromLabels` 从未被调用
6. `||` 的 PHI 未消解

### 根因
`generateLabelDrivenBlockRange` 的 early-exit 行为：当 `return_generated = true` 时，标记所有剩余块为已处理。这会跳过属于不同控制结构的块。

### early-exit 修复方向
在 `generateLabelDrivenBlockRange` 的 early-exit 中：
```zig
if (self.return_generated or self.break_generated) {
    for (i..end_idx) |j| {
        // 不标记控制结构块的起始块（if_then_, logical_merge_ 等）
        const lbl = func.blocks.items[j].label;
        if (std.mem.startsWith(u8, lbl, "if_then_") or
            std.mem.startsWith(u8, lbl, "logical_merge_") or
            std.mem.startsWith(u8, lbl, "logical_rhs_"))
        {
            continue; // 不标记，让后续主循环处理
        }
        try processed.put(j, {});
    }
    return;
}
```

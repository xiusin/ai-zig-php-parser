## 五、已知问题

### 5.1 early-exit 问题（P0，影响 17+ 脚本）

**根因**：`generateLabelDrivenBlockRange` 的 early-exit 行为

```zig
if (self.return_generated or self.break_generated) {
    for (i..end_idx) |j| {
        try processed.put(j, {});  // ← 标记所有剩余块为已处理
    }
    return;
}
```

**问题**：当 `return_generated = true`（如 `if ($n < 4) return true;`），递归调用标记所有剩余块为已处理，包括属于不同控制结构的块（`if_then_`、`logical_merge_`、`logical_rhs_`）。这导致：
- `||`/`&&` 块被跳过（PHI 未消解）
- 后续 `if` 语句的 `if_then_` 块被跳过（`generateIfFromLabels` 从未被调用）

**修复方向**：在 early-exit 中，不标记控制结构块的起始块：
```zig
if (self.return_generated or self.break_generated) {
    for (i..end_idx) |j| {
        const lbl = func.blocks.items[j].label;
        if (std.mem.startsWith(u8, lbl, "if_then_") or
            std.mem.startsWith(u8, lbl, "logical_merge_") or
            std.mem.startsWith(u8, lbl, "logical_rhs_"))
        {
            continue; // 不标记，让后续主循环处理
        }
        try processed.put(j, {});
    }
    return;
}
```

**风险**：需要验证不引入 "unprocessed blocks" 错误。

### 5.3 TypeError: null given（P1，8 脚本）

- 脚本：f057/f070/f080/f085/f095/f110/f161/f163
- 根因：部分是 `||`/`&&` PHI 未消解（同 5.1），部分是运行时库问题（如 f161 的 `json_encode` 输出乱码）

### 5.4 segfault（P1，7 脚本）

## 二、核心变更

### 变更 1: 算术类型推导修复

| 文件 | 变更描述 |
|------|----------|
| `src/aot/runtime_lib_template.zig` | 新增 `tryAsInt()` 辅助函数；`php_add`/`php_sub`/`php_mul` 使用 `tryAsInt` 替代 `isInt()` 检查 |

**根因**: `php_add`/`php_sub`/`php_mul` 仅检查 `lhs.isInt() and rhs.isInt()` 来决定整数路径，未考虑 PHP 的类型推导规则：
- `bool + bool` 应得 `integer`（bool 转为 int）
- `"10" + 20` 应得 `integer`（数字字符串转为 int）
- `null + 5` 应得 `integer`（null 转为 0）

**修复方案**: 新增 `tryAsInt(val: Value) ?i64` 函数，按 PHP 语义将 `int`/`bool`/`null`/纯整数字符串 转为 `i64`。三个算术函数（add/sub/mul）在 `isInt` 检查前先尝试 `tryAsInt`，若两端均可转换则走整数路径（含溢出检测）。

### 变更 2: 字符串插值中数组访问变量解析

| 文件 | 变更描述 |
|------|----------|
| `src/compiler/parser.zig` | `parseInterpolatedString` 中 `$var[key]` 的 key 解析增加 `$` 前缀检测 |

**根因**: 解析器在处理双引号字符串中的 `"$typeArgs[$i]"` 时，将 `$i` 当作字符串字面量 `"i"` 而非变量 `$i`。`parseInt` 失败后直接创建 `literal_string` 节点，未检查 key 是否以 `$` 开头。

**修复方案**: 在 `parseInt` 之前增加 `$` 前缀检测：若 key_text 以 `$` 开头，创建 `variable` 节点而非 `literal_string`。

```zig
if (key_text.len > 0 and key_text[0] == '$') {
    index_node = try self.createNode(.{
        .tag = .variable,
        .main_token = t,
        .data = .{ .variable = .{ .name = try self.context.intern(key_text) } },
    });
} else if (std.fmt.parseInt(i64, key_text, 10)) |int_val| {
    ...
```

## 四、待修复问题分析

### c050 — 变量作用域（alloca 与 var_name_map 寄存器不一致）

**现象**: `$counts` 在 `if ($depth >= 3 || empty($features))` 块内定义后，在块外被加载时报告 "Undefined variable"。

**根因**: IR 中 `$counts` 有两个寄存器：
- `reg_35`（`*runtime.Value`）：alloca 存储（store 写入 `reg_35.*`）
- `reg_36`（`runtime.Value`）：var_name_map 映射的寄存器（load 读取 `reg_36`）

store 和 load 使用不同寄存器，导致 `__def_36` 永远不会被设为 `true`。

**影响**: c050 决策树预测全部错误。

### c019 — 对象引用语义（数组元素方法调用）

**现象**: `"Call to a member function on a non-object"` — 从数组中取出的对象无法调用方法。

**根因**: 对象存储在数组中后，引用语义可能丢失（COW 或值拷贝导致）。

### c043 — 消息队列对象属性变异

**现象**: `pending` 计数少 1，`array_splice` 插入对象后队列长度不正确。

**根因**: `array_splice` 与对象引用交互时的 COW 语义问题。

### c006/c049 — 闭包调用分发

**现象**: 存储在数组中的闭包（`$pattern['handler']`）被调用时返回空值。

**根因**: `($closure)($arg)` 或 `$closure($arg)` 形式的闭包调用，当闭包来自数组元素时分发失败。

### c036 — SIGSEGV（str_replace+闭包）

**现象**: `str_replace` 结合 `var_export` 在闭包上下文中导致段错误。

**根因**: 待定位，可能与 `var_export` 的字符串处理或闭包内存安全相关。

### c045 — 浮点精度边界

**现象**: `round(15.585, 2)` AOT 得 15.59，PHP 得 15.58。

**根因**: 15.585 在 IEEE 754 中无法精确表示，浮点累加顺序差异导致舍入方向不同。归类为浮点精度差异。

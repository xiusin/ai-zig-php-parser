## 二、已完成任务

### 第三轮（P1/P2-a/P2-b/P3-b + P3-a 取消）

#### 2.1 P2-a: generateInstructionSimple lt/le/gt/ge alloca 后缀

**变更**：`generateInstructionSimple` 的 `.lt`/`.le`/`.gt`/`.ge` 四分支 i64 快速路径添加 `alloca_regs` 检查生成 `.*` 后缀，对齐 `writeInlinedConditionExpr` 实现。

**文件**：`src/aot/native_linker.zig`（4 处修改）

#### 2.2 P2-b: .sub/.mul 新增 i64 快速路径 + alloca 后缀

**变更**：
- `.sub`/`.mul` 的 `result_tag == .php_value` 分支新增 `if (self.i64_loop_optimize_active)` 块，生成 `if (isInt() and isInt()) initInt(asInt() OP asInt()) else php_X()`
- `.add`/`.sub`/`.mul` i64 快速路径添加 `alloca_regs` 检查生成 `.*` 后缀

**文件**：`src/aot/native_linker.zig`（3 处修改）

#### 2.3 P3-a: @branchHint(.likely)（取消）

**结论**：交接文档第 5.3 节明确"性能影响微小，暂不处理"。Zig 的 `if-else` 表达式不支持 `@branchHint`，重构为 labeled block 会令生成代码极度冗长（11 处 i64 快速路径），维护成本高而收益微小。

#### 2.4 P3-b: 全量测试脚本并行优化（编译锁版本）

**变更**：
- 编译步骤通过 `mkdir $COMPILE_LOCK` 锁串行化（AOT 中间产物路径固定 `.zigphp_aot_build`，并行编译不安全）
- 运行步骤并行执行（AOT 运行 + PHP 对比，无共享状态）
- 进度提示 `[i/N]` 格式
- `PARALLEL_JOBS` 环境变量控制并行度（默认 CPU 核心数）

**文件**：`scripts/full_regression_test.sh`（重写）

#### 2.5 P1: 编译时类型分析省略 isInt() 运行时检查

**变更**：
- 新增字段 `i64_loop_known_int_regs: ?*const std.AutoHashMap(usize, void)`，记录循环内已知整数寄存器
- 新增 `collectKnownIntRegs`（分发函数）：区分全局变量路径和 alloca 路径
- 新增 `collectKnownIntRegsGlobal`：检查 `global_set` 初始值为 const_int + body 无非 increment `global_set`，收集所有 `global_get` 结果寄存器
- 新增 `collectKnownIntRegsAlloca`：检查 `store` 初始值为 const_int + body 无非 increment `store`，收集所有 `load` 结果寄存器
- 修改 `generateOptimizedForLoop`：调用 `collectKnownIntRegs`，设置 `i64_loop_known_int_regs`
- 修改 `writeInlinedConditionExpr` lt/le/gt/ge 四分支：检查 `i64_loop_known_int_regs` 纠正类型为 `.i64`，命中已有无 `isInt()` 检查的快速路径

**安全条件**：
1. 循环变量初始值为 `const_int`（编译时整数常量）
2. body 块中无非 increment/decrement 的重新赋值（允许 `$i++` 写回，拒绝 `$i = "hello"` 等）

**生成代码对比**（`simple_loop.php`）：

变更前：
```zig
if (!((if (reg_1.isInt() and reg_2.isInt()) (reg_1.asInt() < reg_2.asInt()) else (try runtime.php_lt(reg_1, reg_2)).toBool()))) { @branchHint(.unlikely); break; }
```

变更后：
```zig
if (!(reg_1.asInt() < reg_2.asInt())) { @branchHint(.unlikely); break; }
```

**文件**：`src/aot/native_linker.zig`（1 字段 + 3 函数 + 4 分支类型纠正）

### 第四轮（P2-a 扩展/P2-b 扩展/P3 真正并行）

#### 2.6 P2-a 扩展: tryEmitI64FastPath 全分支添加 known_int_regs 检查

**变更**：`tryEmitI64FastPath` 的全九处（`php_increment`/`php_decrement` + `php_lt`/`php_le`/`php_gt`/`php_ge` + `php_add`/`php_sub`/`php_mul`）添加 `known_int_regs` 检查，已知整数操作数省略 `isInt()` 运行时检查，同时添加 alloca `.*` 后缀。

**优化前**：`if (reg.isInt()) initInt(asInt()+1) else php_increment()`
**优化后**（known_int_regs 命中）：`initInt(asInt()+1)`

**文件**：`src/aot/native_linker.zig`（9 处修改）

#### 2.7 P2-b 扩展: generateInstructionSimple lt/le/gt/ge 类型纠正

**变更**：`generateInstructionSimple` 的 lt/le/gt/ge 四分支 `const lhs_corrected` → `var lhs_corrected`，添加 `i64_loop_known_int_regs` 检查，已知整数寄存器纠正为 `.i64`，命中纯 i64 路径（无 isInt 检查）。

**注意**：add/sub/mul 未处理（result_type 纠正不安全，P2-a 已覆盖 call 路径）。

**文件**：`src/aot/native_linker.zig`（4 分支类型纠正）

#### 2.8 P3: AOT 编译器进程唯一临时目录（真正并行编译）

**变更**：

## 五、已知问题

### 5.1 P3 失去 main.zig 增量缓存

**现状**：P3 改为进程唯一临时目录后，失去 `compileToExecutable` 中 line 19156-19170 的 main.zig 内容检查优化（增量缓存）。

**影响**：单次编译时间可能略增（每次都需复制运行时库）。

**缓解**：并行编译总时间大幅缩短，整体收益正向。后续可用符号链接减少 I/O。

### 5.2 P2-b add/sub/mul 未处理

**现状**：`generateInstructionSimple` 的 `.add`/`.sub`/`.mul` 原生指令路径未添加 `known_int_regs` 类型纠正。

**原因**：result_type 纠正不安全（result 可能不是循环变量，纠正为 i64 会影响后续代码生成）。

**缓解**：P2-a 已覆盖 call 路径（`php_add`/`php_sub`/`php_mul`），原生指令路径影响有限。

### 5.3 P3 每次编译复制运行时库

**现状**：P3 每次编译都需复制运行时库文件到临时目录。

**影响**：I/O 开销（文件较小 ~100KB，影响有限）。

**解决方案**：改为符号链接（symlink）。

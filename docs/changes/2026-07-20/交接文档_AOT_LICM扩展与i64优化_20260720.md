## 一、本会话已完成任务

### 1. P4: IR 层 LICM 根因定位（已完成）

**方法**: 启用 IR 层 LICM，编译 `test_063_sorting_algorithms.php`，对比启用/禁用的生成代码。

**根因1: 状态机块编号破坏**
- 代码生成器使用状态机模式（`current_block` switch）
- IR 层 LICM 的 `getOrCreatePreHeader` 插入新块后重新编号 block index
- 导致状态机的 case 编号错乱，缺少 `case 3` 等块
- mergeSort 输出缺少元素，出现 "array offset on null" 错误

**根因2: i64 快速路径类型分析破坏**
- LICM 将 `const_int` 指令移到循环外
- 循环内的类型分析无法识别已知整数寄存器
- 生成代码从 `reg_16 = runtime.Value.initInt(reg_47.asInt() + reg_9.asInt())` 退化为 `reg_16 = if (reg_47.isInt() and reg_9.isInt()) ... else ...`

**结论**: IR 层 LICM 保持 `false`（`optimizer.zig` 第 213 行 `.licm = false`）。修复需深入重构，风险高。

### 2. P3: 代码生成层 LICM 扩展——单独 load 提升（已完成）

**文件**: `src/aot/native_linker.zig` → `hoistLoopInvariantsAtCodegen`

**变更**:
- 从仅支持 `load + call(纯函数)` 相邻对 → 扩展为也支持单独 `load(循环不变地址)` 提升
- `generateWhileLoopStructuredNew` 添加 LICM 调用（原仅 `generateForLoopStructuredNew` 有）
- **修复 modified_addrs 收集缺陷**: 从只扫描 `header/body_start/increment` 三块 → 遍历 `loop.blocks` 全部块，修复 c014（BFS getNeighbors null 错误）和 c019 回归

### 3. P3: 覆盖率报告脚本（已完成）

**文件**: `scripts/aot_coverage_report.sh`（新增）

通过 `ZIGPHP_AOT_STATS=1` 环境变量驱动，编译所有测试脚本并汇总 i64 快速路径激活率（for/while 循环分别统计）。

### 4. P1: 代码生成层 LICM 算术运算提升（已完成）

**文件**: `src/aot/native_linker.zig` → `hoistLoopInvariantsAtCodegen`

**算法**: 迭代不动点收集操作数不变的 `.add/.sub/.mul` 指令
1. 构建 `loop_defined_regs`（循环内定义的所有寄存器）
2. 操作数不变 = 在 `invariant_regs` 中 或 不在 `loop_defined_regs` 中（循环外定义）
3. 迭代直到不动点
4. 通过 `generateInstructionSimple` 生成到临时缓冲区，避免代码重复

**关键修复**: 移除了 `const_int` 的不变性假设——循环体内的 `const_int` 结果（如 `reg_27 = initInt(31)`）在循环体执行时才赋值，不能视为循环不变。此修复解决了 c033（Bloom filter 填充率错误）回归。

## 四、核心代码结构

### 4.1 LICM 调用链

```
generateForLoopStructuredNew  ──→ hoistLoopInvariantsAtCodegen
generateWhileLoopStructuredNew ──→ hoistLoopInvariantsAtCodegen
```

### 4.2 hoistLoopInvariantsAtCodegen 流程

```
1. 收集 modified_addrs（遍历 loop.blocks 所有块的 store 目标）
2. 扫描 loop_blocks 中的 load 指令：
   a. 地址循环不变？（不在 modified_addrs 中）
   b. 匹配 load + call(纯函数)？→ 提升到循环前
   c. 无匹配 call？→ 提升单独 load
3. P1 算术提升：
   a. 构建 loop_defined_regs
   b. 初始化 invariant_regs（仅已提升的 load 结果）
   c. 迭代不动点收集 .add/.sub/.mul
   d. 通过 generateInstructionSimple 生成到临时缓冲区
4. 标记所有提升的指令（hoisted_instructions map）
5. 循环体生成时跳过已提升指令（generateInstructionSimple 开头检查 isInstructionHoisted）
```

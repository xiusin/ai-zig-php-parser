### 2.1 本轮修复（第四轮）

| 编号 | 缺陷 | 根因 | 修复方案 | 修复脚本 |

| AOT-REF-003 | 静态方法调用引用参数缺失 | `generateStaticMethodCall` 仅 `generateExpression` 所有参数，未处理 by-reference 参数 | 添加 `make_ref + alloca + writeback` 逻辑，与 `generateMethodCall` 一致 | c003: FAIL→PASS |

### 2.2 变更文件明细

#### `src/aot/ir_generator.zig`（+110 行）

1. **预扫描 ref_params 索引偏移修正**（约 line 818）
   - 修复前：`try ref_indices.append(self.allocator, @intCast(i + 1));`
   - 修复后：`const offset: u32 = if (method_data.modifiers.is_static) 0 else 1; try ref_indices.append(self.allocator, @intCast(i + offset));`

2. **`generateStaticMethodCall` 引用参数处理**（约 line 7674）
   - 修复前：`args[i] = try self.generateExpression(arg_idx);`（无引用处理）
   - 修复后：添加完整的 ref_params 查找 + make_ref + alloca + writeback 逻辑
   - 静态方法 `param_idx = i`（无 `$this` 偏移）
   - 调用后执行 `global_set` 写回引用参数新值
   - 查找路径：先精确匹配 `ClassName::methodName`，再查 `function_ref_params`，最后回退搜索 module 函数

3. **三级嵌套数组赋值**（约 line 4095）
   - 修复前：`array_ensure` 链 + `array_push`（COW 克隆未写回）
   - 修复后：
     - 2 键 push → `php_property_array_push_key2_with_obj`
     - 2 键 set → `php_property_array_set_key2_with_obj`
     - 更深层嵌套保留 `array_ensure` 回退路径

#### `src/aot/runtime_lib_template.zig`（+80 行）

1. **`php_crc32` 修复**（约 line 27097）
   - 修复前：`const signed: i32 = @bitCast(crc); return Value.initInt(@intCast(signed));`
   - 修复后：`return Value.initInt(@intCast(crc));`

2. **新增 `php_property_array_push_key2_with_obj`**（约 line 19065）
   - 处理 `$obj->prop[key1][key2][] = value`
   - 导航路径：`obj.getPropertyDirect(name)` → `arr.get(key1)` → `sub_arr.get(key2)` → `sub2_arr.push(value)`
   - 每层自动创建不存在的子数组

3. **新增 `php_property_array_set_key2_with_obj`**（约 line 19100）
   - 处理 `$obj->prop[key1][key2] = value`
   - 同上导航路径，最终 `sub_arr.set(key2, value)`

4. **`PHPArray.release` GC 延迟释放**（约 line 2032）
   - 修复前：`ref_count==0 → deinit()`
   - 修复后：`ref_count==0 && gc_info.buffered && !gc_in_progress → gcBufferArray(self)`（延迟释放）

5. **`PHPObject.release` GC 延迟释放**（约 line 17931）
   - 同 PHPArray 逻辑

6. **`PHPClosure.release` GC 延迟释放**（约 line 2825）
   - 同 PHPArray 逻辑

## 三、待办任务

### 3.1 高优先级（P0）— 已全部完成

#### ~~待办-1: c028 ReleaseFast 括号表达式求值差异~~ ✅ 已修复

- **修复方案**：GC 保守策略 — `gcCollectCycles` 改为仅释放 `ref_count==0` 的对象，跳过 MarkGray/Scan 循环检测
- **根因**：GC 在 `gcCollectCycles` 开始时清除所有 `gc_info.buffered` 标志，导致 `release` 在 GC 期间误释放仍在 `cycle_roots` 中的对象
- **修复脚本**：c028 SEGV → PASS

#### ~~待办-2: c046 Large Scale 段 GC 崩溃~~ ✅ 已修复

- **修复方案**：同待办-1（GC 保守策略）
- **修复脚本**：c046 SEGV → PASS

### 3.2 中优先级（P1）

#### 待办-3: c043 TypeError 参数类型检查

- **现象**：PHP 在 `reject(null)` 时抛出 `TypeError: Argument #1 ($messageId) must be of type string, null given`，AOT 不检查类型约束继续执行
- **影响**：AOT 输出与 PHP 不一致，且 AOT 继续执行导致后续逻辑错误（如 `$msg4->id` 在 null 上访问属性）
- **修复方向**：在 AOT 方法调用时检查参数类型提示，对类型不匹配抛出 TypeError 异常
- **影响范围**：所有带类型约束的方法调用
- **影响文件**：`src/aot/native_linker.zig`（方法调用代码生成）、`src/aot/ir_generator.zig`（参数类型信息传递）
- **落地成本**：高 — 需要在 IR 中传递参数类型信息，在 native_linker 中生成类型检查代码

#### ~~待办-4: c037/c049 编译失败~~ ✅ c049 已修复，c037 转为 DIFF

- **c049**：`typesystem_generic_covariant_pattern.php` — 原 COMPILE_FAIL，现 PASS（GC 修复消除了编译期崩溃）
- **c037**：`functional_curry_immutable.php` — 原 COMPILE_FAIL，现能编译但有 DIFF（柯里化 COW 差异：原始数组被修改）
- **修复方向**：c037 需修复闭包捕获数组的 COW 隔离

### 3.3 低优先级（P2）

#### 待办-5: 四级及以上嵌套数组写回

- **现状**：当前仅支持到 2 键 push/set（`php_property_array_push_key2_with_obj`），更深层嵌套走 `array_ensure` 回退路径，COW 克隆未写回
- **影响**：极少数深层嵌套场景
- **修复方向**：可考虑递归实现或生成更多层级的专用函数

#### 待办-6: GC 改为增量式收集

- **现状**：当前批量扫描在大规模数据下容易触发 use-after-free
- **修复方向**：改为增量式 GC，降低单次扫描的内存压力
- **落地成本**：高

## 五、测试方法论

### 5.1 编译与测试命令

```bash
# 编译验证
timeout 120 zig build

# 单脚本编译
timeout 60 zig-out/bin/php-interpreter --compile --no-debug-info <script.php>

# 单脚本测试
timeout 10 php <script.php> > /tmp/php_out.txt 2>&1
timeout 10 ./aot_compile_<name> > /tmp/aot_out.txt 2>&1
diff /tmp/php_out.txt /tmp/aot_out.txt

# Debug 模式编译（用于调试 ReleaseFast 差异）
timeout 60 zig-out/bin/php-interpreter --compile --no-debug-info --optimize=debug <script.php>

# 批量测试
for f in fuzzy_scripts_715/pass/*.php; do
  name=$(basename "$f" .php)
  timeout 60 zig-out/bin/php-interpreter --compile --no-debug-info "$f" 2>/dev/null
  bin="fuzzy_scripts_715/pass/aot_compile_${name}"
  diff <(timeout 10 php "$f" 2>/dev/null) <(timeout 10 "$bin" 2>/dev/null) && echo "PASS: $name" || echo "DIFF: $name"
done

# 清理编译产物
find fuzzy_scripts_715 -name 'aot_compile_*' -type f -delete
rm -rf .zigphp_aot_build
```

- **SEGV**：段错误（需修复）
- **COMPILE_FAIL**：AOT 编译失败

## 九、注意事项

1. **编译产物命名**：所有 AOT 编译产物必须以 `aot_compile_{filename}` 命名，禁止与 PHP 源文件同名
2. **PHP 脚本保护**：任何时候都不可删除 PHP 的原始脚本文件（`.php` 文件）
3. **测试超时**：所有测试命令必须带 `timeout` 包裹，单脚本执行不超过 10 秒
4. **编译产物清理**：测试完成后必须删除编译产物（`find fuzzy_scripts_715 -name 'aot_compile_*' -delete && rm -rf .zigphp_aot_build`）
5. **超大文件修改**：`native_linker.zig`（18,828 行）和 `ir_generator.zig`（9,513 行）为超大文件，修改前必须 grep 搜索已有模式
6. **GC 修复影响面**：本轮 GC 延迟释放修改影响所有 PHPArray/PHPObject/PHPClosure 的释放路径，需全量回归验证

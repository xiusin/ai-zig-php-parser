# AOT 弱类型值转换与 GC 增量批次收集 变更摘要

> 日期：2026-07-17
> 轮次：第十一轮
> 全量测试：pass 37/37 + fail_runtime 17/17 + fuzzy_scripts_73 7/7 = 61/61 ALL PASS, DIFF=0

---

## 1. TL;DR

本轮完成两项 P1 级后续建议：
1. **弱类型值转换**：类型检查通过后对标量参数实际转换值（string→int/float、bool→int/float、float→int、int/float/bool→string）
2. **GC 增量批次收集**：保守策略下每次最多处理 64 个根，未处理的保留到下次，减少单次 GC 暂停时间

## 2. 影响范围

| 模块 | 影响面 | 风险等级 |
|------|--------|----------|
| 参数加载代码生成 | 所有带 PHP 类型声明的函数参数 | 中（已回归验证） |
| `checkSingleType` 弱类型规则 | 所有参数类型检查路径 | 低 |
| GC 收集循环 | 所有 AOT 程序的内存管理 | 低（保守策略不变，仅改批次大小） |

## 5. 详细变更分析

### 5.1 弱类型值转换 `php_coerce_value`

**位置**：`runtime_lib_template.zig` ~line 5893

**逻辑**：
- 组合类型（含 `|` 或 `&`）→ 不转换（只做类型检查）
- `int`：`isFloat()/isBool()/isNull()/isString()` → `Value.initInt(val.toInt())`
- `float`：`isInt()/isBool()/isNull()/isString()` → `Value.initFloat(val.toFloat())`
- `bool`：→ `Value.initBool(val.toBool())`
- `string`：`isInt()/isFloat()/isBool()/isNull()` → `Value.initString(val.toString(allocator))`

### 5.2 参数加载代码修改

**位置**：`native_linker.zig` ~line 8846

**生成代码模式**（有 PHP 类型时）：
```zig
var __pv = if (args.len > N and !args[N].isMissing())
    (if (args[N].isNull() and true) args[N]  // nullable + null → 不转换
     else runtime.php_coerce_value(args[N], "int", runtime.runtime_allocator))
    else runtime.Value.initNull();
```

**nullable 处理**：读取 `func.param_nullable[args_index]`，当 nullable=true 且值为 null 时不做转换（保持 null），避免 `?string` 参数收 null 被转为 `""`。

### 5.3 `checkSingleType` 弱类型规则补全

| 新增规则 | PHP 语义 |
|----------|----------|
| `expected=int/float, got=bool` | bool→int/float 弱类型转换 |
| `expected=int, got=float` | float→int 弱类型转换（可能有精度损失警告，忽略） |

### 5.4 GC 增量批次收集

**位置**：`runtime_lib_template.zig` ~line 904

**变更前**：
```zig
for (items) |r| { ... }
cycle_roots.clearRetainingCapacity();
```

**变更后**：
```zig
const batch_end = if (force) total else @min(total, GC_BATCH_SIZE);
for (cycle_roots.items[0..batch_end]) |r| { ... }
const remaining = total - batch_end;
if (remaining > 0) {
    for (0..remaining) |i| { cycle_roots.items[i] = cycle_roots.items[batch_end + i]; }
    cycle_roots.items.len = remaining;
} else {
    cycle_roots.clearRetainingCapacity();
}
```

- `force=true`（`php_collect_cycles()` 显式调用）→ 处理全部
- `force=false`（阈值触发）→ 最多处理 64 个，未处理的保留到下次

## 6. 影响与风险评估

- **破坏式变更**：否
- **变更影响范围**：所有带类型声明的函数参数加载路径；所有 GC 收集路径
- **需要特别注意的点**：
  - nullable 参数 null 值不转换是关键修复，否则 `?string` 收 null 会输出 `''` 而非 `NULL`
  - `std.copyForwards` 在 Zig 0.16 不存在，改用简单 for 循环
- **复测路径**：`batch_test_pass.sh` + `batch_test_aot.sh` + `full_scan_aot.sh`

## 7. 遗留问题

无遗留问题。全量 61/61 PASS。

GC 完整循环检测（MarkGray/Scan/CollectWhite）仍未启用，根因是 AOT 缺少栈根扫描。增量批次处理仅优化了保守策略的暂停时间，不解决循环引用泄漏问题。

## 8. 后续开发建议

| 优先级 | 建议 | 影响面 | 落地成本 |
|--------|------|--------|----------|
| P2 | 系统死代码清理（rt_*.zig 26,880 行 + runtime/ ~11,000 行） | 可维护性 | 低（零风险） |
| P2 | nanbox_abi 常量冲突统一 | 类型安全 | 中 |
| P3 | GC 栈根扫描 → 启用完整循环检测 | 内存泄漏修复 | 极高（架构级） |
| P3 | 返回类型声明的值转换（return type coercion） | 类型安全完整性 | 低 |

# AOT 参数类型检查回归修复

**日期**: 2026-07-17  
**Hash**: typecheck_regression_c012  
**模块**: AOT IR 生成器 — 匿名类接口解析

## 1. 高层摘要 (TL;DR)

在第六轮参数类型检查修复后，引入了两个回归 BUG：
- **c012**: 匿名类 `new class(...) implements Command { ... }` 实现 `Command` 接口，但运行时 `implementsInterface` 检查失败，导致 `TypeError`
- **c020**: deepmerge 输出值丢失（`logging.level: debug` → 空字符串，`feature.flags.new_ui: true` → `NULL`）

c012 修复通过：IR 生成器中匿名类的接口解析同时支持 `.named_type` 和 `.variable` 标签。  
c020 DIFF 保留（非参数类型检查导致，需单独分析）。

## 2. 根因分析

### 2.1 c012 匿名类接口解析失败

**问题**: `new class(...) implements Command { ... }` 生成 TypeError。

**根因**:
1. Parser 对 `implements` 列表中的接口名使用 `parsePrimary()` 解析
2. `parsePrimary()` 对普通标识符 `Command` 生成 `.variable` 节点（不是 `.named_type`）
3. IR 生成器中只检查 `.named_type` 标签，跳过了 `.variable` 节点
4. 匿名类的 TypeDef 中 `interfaces` 字段为空
5. native_linker 中 `td.interfaces.len > 0` 检查失败，不生成 `_meta.interfaces = ...` 代码
6. 运行时 `implementsInterface("Command")` 返回 false

**修复**: 在 IR 生成器中同时检查 `.named_type` 和 `.variable` 标签。

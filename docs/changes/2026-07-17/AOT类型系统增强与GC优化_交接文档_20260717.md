## 三、核心变更详情

### 3.1 变更文件清单

| 文件 | 变更内容 |
|------|----------|
| `src/compiler/ast.zig` | `function_decl` 节点新增 `return_type: ?Index` 字段 |
| `src/compiler/parser.zig` | `parseFunction` 存储返回类型而非丢弃 |
| `src/aot/ir.zig` | `IR.Function` 新增 `param_types`/`param_nullable`/`param_names`/`php_return_type`/`php_return_nullable` 字段 |
| `src/aot/ir_generator.zig` | `generateFunctionDecl`/`generateMethodDecl` 提取参数和返回类型；嵌套数组 push 写回逻辑 |
| `src/aot/native_linker.zig` | 参数类型检查代码生成；`resolveTypeSpecials` 方法；`writeReturnStmt`/`generateReturnStr` 辅助方法；10+处返回点统一；参数加载 `php_coerce_value` 调用 |
| `src/aot/runtime_lib_template.zig` | `php_coerce_value` 新增；`checkSingleType` 弱类型规则补全；GC 增量批次 `GC_BATCH_SIZE=64`；GC 循环检测算法保留但未启用 |
| `src/aot/optimizer.zig` | 保留 `no_deref`/`cow` 标志 |
| `src/shared/nanbox_abi.zig` | `TYPE_REF` 值从 `0x0003...` 改为 `0x0002...`；补全 `TYPE_BIGINT`/`TYPE_RESOURCE` |

### 3.2 各任务实现要点

#### P1-1: static 后期静态绑定

- `resolveTypeSpecials` 不替换 `static`（保留到运行时）
- `checkSingleType` 运行时通过 `getCurrentCalledClass()` 解析 `static` 为实际类名

#### P1-2: 组合类型中 self/parent 替换

- 新增 `resolveTypeSpecials(ptype, class_name, parent_name)` 方法
- 逐组件替换 `self` → `class_name`，`parent` → `parent_name`（支持 `self|null` 等组合类型）

#### P1-3: 全局函数参数类型检查

- `IR.Function` 新增 `param_types: []const []const u8`、`param_nullable: []const bool`、`param_names: []const []const u8`
- `generateFunctionDecl` 从 AST 提取参数类型声明填充
- `native_linker` 在函数 prologue 生成 `php_check_param_type` 调用（仅全局函数，方法已在 `generateMethodDecl` 处理）

#### 弱类型匹配规则

- `checkSingleType` 新增规则：
  - 数字字符串 → int/float
  - int/float/bool → string
  - float/string → bool
  - bool → int/float
  - float → int

#### P2-1: callable 深度验证

- `checkSingleType` 的 `callable` 分支复用 `php_is_callable` 做深度验证：
  - 函数名存在性检查
  - 数组格式 `[class, method]` 检查
  - `__invoke` 方法检查

#### P2-2: 四级以上嵌套数组 push 写回

- `ir_generator.zig` 的 `array_access` 写回逻辑修改：
  - `is_push_assignment` 路径保存中间层 `array_ensure` 寄存器
  - 逐层 `array_set` 写回，修复 COW 克隆后中间层丢失

#### P1-值转换: php_coerce_value

- 新增 `php_coerce_value(val, expected_type, allocator)` 函数
- 仅对标量类型（int/float/bool/string）执行转换，组合类型不转换
- 参数加载时：有 PHP 类型声明 → 调用 `php_coerce_value`；nullable + null → 不转换

#### P1-4: GC 增量批次收集

- 新增 `GC_BATCH_SIZE = 64` 常量
- `gcCollectCycles` 改为增量批次：每次最多处理 64 个根，未处理的移到数组前端保留到下次
- `force=true`（`php_collect_cycles()` 显式调用）→ 处理全部

#### P3-返回值: 返回类型声明的值转换

**全链路修改**：
1. `ast.zig`: `function_decl` 新增 `return_type: ?Index = null`
2. `parser.zig`: `parseFunction` 将 `parseType()` 结果存入 `return_type_idx`
3. `ir.zig`: `IR.Function` 新增 `php_return_type: ?[]const u8` 和 `php_return_nullable: bool`
4. `ir_generator.zig`: `generateFunctionDecl`/`generateMethodDecl` 提取返回类型填充 `func.php_return_type`
5. `native_linker.zig`:
   - `generateFunction` 设置 `self.current_return_type`/`current_return_nullable`
   - 新增 `writeReturnStmt(writer, reg_id, is_alloca, indent)` — writer 版本
   - 新增 `generateReturnStr(reg_id, is_alloca, indent)` — 字符串版本（用于 allocPrint 路径）
   - 10+ 处 return 生成点替换为统一辅助方法

**生成代码模式**：
```zig
// 有返回类型声明时：
return if (true and reg_0.isNull()) reg_0
     else runtime.php_coerce_value(reg_0, "int", runtime.runtime_allocator);
// 无返回类型声明时：
return reg_0;
```

#### P2-nanbox: 常量冲突统一

**冲突**：
- `shared/nanbox_abi.zig`: `TYPE_REF = 0x0003000000000000`
- `aot/nanbox_abi.zig`: `TYPE_BIGINT = 0x0003000000000000`

**修复**：shared 版与 aot 版统一：
```
TYPE_REF:      0x0002800000000000 (从 0x0003 改为 0x0002)
TYPE_BIGINT:   0x0003000000000000 (新增)
TYPE_RESOURCE: 0x0003800000000000 (新增)
```

#### P3-GC循环: 评估后回退

**尝试**：将保守策略替换为 MarkGray → Scan → CollectWhite 三阶段完整算法

**结果**：SEGV (exit 139)

**根因分析**：
1. AOT 生成的代码中，部分栈变量赋值路径未调用 `retain()`
2. MarkGray 递减内部引用后，这些对象的 ref_count 误判为 0
3. CollectWhite 阶段释放仍在栈上使用的对象 → SEGV

**结论**：算法本身正确，但需要先修复所有 retain/release 不精确问题。已回退到保守策略，代码中保留了完整算法实现（注释说明未启用原因）。

| 系统死代码 | rt_*.zig 26,880 行 + runtime/ ~11,000 行 | 未清理 | 低（零风险） | 用户表示自行处理 |

### 4.3 GC 循环检测技术细节

完整算法已实现并保留在 `runtime_lib_template.zig` 中（~line 979-1389）：

| 阶段 | 函数 | 作用 |
|------|------|------|
| MarkGray | `gcMarkGray`/`gcMarkGrayArray`/`gcMarkGrayObject`/`gcMarkGrayClosure` | 递减所有内部引用的 ref_count |
| Scan | `gcScan`/`gcScanArray`/`gcScanObject`/`gcScanClosure` | ref_count > 0 → black（存活），== 0 → white（垃圾） |
| ScanBlack | `gcScanBlackArray`/`gcScanBlackObject`/`gcScanBlackClosure` | 恢复 black 对象引用的子对象的 ref_count |
| CollectWhite | `gcCollectWhiteArray`/`gcCollectWhiteObject`/`gcCollectWhiteClosure` | 释放所有 white 对象 |

**启用方法**：将 `gcCollectCycles` 中的保守策略替换为三阶段调用即可（代码已在注释中保留）。

## 八、架构关键路径

```
PHP 源码
  ↓
parser.zig (AST 生成，含 return_type 字段)
  ↓
ast.zig (function_decl 节点定义)
  ↓
ir_generator.zig (IR 生成，提取参数/返回类型)
  ↓
ir.zig (IR.Function 定义，含 param_types/php_return_type)
  ↓
optimizer.zig (IR 优化，保留 no_deref/cow 标志)
  ↓
native_linker.zig (Zig 代码生成)
  ├── 参数加载: php_coerce_value (弱类型值转换)
  ├── 函数 prologue: php_check_param_type (参数类型检查)
  ├── 返回点: writeReturnStmt/generateReturnStr (返回值转换)
  └── 生成 runtime_lib.zig + main.zig
  ↓
runtime_lib_template.zig (运行时模板)
  ├── php_coerce_value (标量值转换)
  ├── checkSingleType (弱类型匹配 + static/self/parent/callable)
  ├── gcCollectCycles (保守策略 + 增量批次 GC_BATCH_SIZE=64)
  └── [未启用] gcMarkGray/gcScan/gcCollectWhite (完整循环检测)
  ↓
AOT 可执行文件
```

## 二、核心变更

### 变更 1: 实现 `spl_object_id` / `spl_object_hash`

| 文件 | 变更描述 |
|------|----------|
| `src/aot/runtime_lib_template.zig` | 新增 `php_spl_object_id()` 和 `php_spl_object_hash()` 函数实现；新增 6 个 wrapper 函数；在 `builtin_function_map` 中注册 7 个函数 |
| `src/aot/native_linker.zig` | 在 `builtin_map` 中注册 `spl_object_id` 和 `spl_object_hash` |

**实现细节**:
- `spl_object_id`: 取 `PHPObject` 指针地址的低 31 位作为整数 ID
- `spl_object_hash`: 将指针地址格式化为 16 位十六进制字符串
- 同时在 `builtin_function_map` 注册 wrapper，确保动态分发路径（`lookupBuiltinFunction`）也可调用

### 变更 2: 移除 `range` 关键字

| 文件 | 变更描述 |
|------|----------|
| `src/compiler/keyword_lookup.zig` | 从 `keyword_map` 中移除 `.{ "range", .k_range }` 条目 |
| `src/compiler/parser.zig` | 更新 `for range N` 语法：改用标识符文本匹配 `"range"` 而非 `k_range` token tag；移除表达式解析器中的 `.k_range` case |

**根因**: `range` 在标准 PHP 中是内置函数（`range(0, 10)`），不是语言关键字。解析器将其注册为 `k_range` 关键字导致函数调用 `range()` 在解析阶段失败。

### 变更 3: PHP 8.0+ 函数注册到 `builtin_function_map`

| 文件 | 变更描述 |
|------|----------|
| `src/aot/runtime_lib_template.zig` | 新增 wrapper: `wrapBuiltin_str_starts_with`, `wrapBuiltin_str_ends_with`, `wrapBuiltin_str_contains`, `wrapBuiltin_spl_object_id`, `wrapBuiltin_spl_object_hash`, `wrapBuiltin_array_splice`；在 `builtin_function_map` 中注册上述函数 |

**根因**: 这些函数已在 `native_linker.zig` 的 `builtin_map` 中注册（用于编译时直接调用生成），但未在 `runtime_lib_template.zig` 的 `builtin_function_map` 中注册（用于运行时动态分发 `lookupBuiltinFunction`）。两条路径需同时注册。

## 三、核心根因分析：PHI 节点未处理

### 问题现象

在 `foreach` 循环内嵌套 `if` 块中修改变量，变量值在下一迭代中丢失：

```php
foreach ($this->routes as $network => $gw) {
    if (str_starts_with($dest, $network)) {    // 外层 if
        $len = strlen($network);
        if ($len > $bestLen) {                  // 内层 if
            $bestMatch = $gw;                  // 赋值丢失！
            $bestLen = $len;                   // 赋值丢失！
        }
    }
    echo "bestMatch=$bestMatch bestLen=$bestLen\n";  // AOT: bestMatch= bestLen=
}
```

### 根因定位

**IR 层面**: IR 生成器使用 SSA（静态单赋值）形式，每次变量赋值创建新寄存器。

**Native Linker 层面**: `tryGenerateSimpleIfElsePattern` 函数将 if/else 块生成为 Zig `if/else` 语句。PHI 节点应在 merge 块中将分支结果合并回原始寄存器。

**缺陷位置**: `src/aot/native_linker.zig` 第 11810-11816 行：
```zig
.phi => {
    // PHI节点在terminator中处理，这里跳过
    if (inst.result) |reg| {
        try writer.print("    // PHI: reg_{d} (handled in terminator)\n", .{reg.id});
    }
},
```

PHI 节点仅生成注释 `// PHI: reg_X (handled in terminator)`，**未生成实际寄存器拷贝代码**。变量赋值在 if 分支内进入临时 SSA 寄存器，PHI 应将临时寄存器合并回变量原始寄存器，但实际未执行。

### 影响范围

| 脚本 | 影响描述 |
|------|----------|
| c029 | `$bestMatch`/`$bestLen` 在 foreach+嵌套 if 中丢失 |
| c050 | `$counts` 在 if 分支内定义后不可见 |
| c019 | 对象引用语义（与 PHI 叠加） |
| c043 | `array_splice` 修改对象属性后结果不可见 |
| c006 | 闭包参数传递（可能涉及 PHI） |
| c049 | 字符串字面量（可能涉及 PHI） |

### 修复方向

需要在 `tryGenerateSimpleIfElsePattern` 函数中，在每个分支块末尾（terminator 之前）插入 PHI 寄存器拷贝：

```
// then 分支末尾（br 之前）:
reg_result = reg_then_incoming;

// else 分支末尾（br 之前）:
reg_result = reg_else_incoming;
```

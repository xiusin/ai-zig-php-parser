## 1. 本次问题与修复结果

### 1.1 触发用例

用例：`examples/tests/basic/test_magic_and_props.php`

该用例同时覆盖：

- 三元表达式与分支合流（需要 PHI 语义正确）
- 严格比较 `===/!==`（需要 identical/not_identical 指令落地）
- 魔术常量 `__LINE__/__FILE__/__DIR__`（需要 token 位置到行列的映射）
- 类/对象（属性与元信息初始化路径）

### 1.2 表现与根因（核心）

问题表现（AOT 产物）：

- 三元表达式分支结果错误（常见表现为“总走 else/结果恒错”）
- `__LINE__` 输出为 `0`（不随源码行变化）

根因归类：

1) **SSA 的 PHI 语义在 native 后端降级时缺失**

- IR 生成层会发射 `phi` 来合并 then/else 的结果
- 若后端不实现 `phi`，合流块中的目标寄存器值不可靠，直接污染后续条件/输出

2) **严格比较与常量生成在简化路径缺失/不完整**

- `identical/not_identical` 若未生成，会导致条件寄存器未赋值或走错误默认值
- `const_*`（如 const_null/const_bool/const_int/const_string）在某些路径若输出不正确，会导致 runtime 调用参数错误或条件恒错

3) **AOT token 到 line/column 的映射断层**

- 解释器路径可以通过 VM 的 `current_source` 计算行号
- AOT 路径将 parser token 转换为 AOT token 时把 `line/column` 写死为 0，导致 `__LINE__` 永远为 0

4) **临时 slice 生命周期隐患**

- 代码生成中出现对临时聚合 `&.{...}` 的长期引用风险（用于 `.call.args`），可能产生悬垂指针/不稳定行为

### 1.3 修复点摘要（文件级）

以下改动已落地并通过用例验证：

- native 后端：补齐 PHI 下降（控制流状态机引入 `prev_block`，在进入块时 `switch(prev_block)` 执行 PHI 赋值）
  - 位置：[native_linker.zig](file:///Users/xiusin/Desktop/zig-php/zig-php-parser/src/aot/native_linker.zig)
- native 后端：在简化指令生成路径中补齐 `identical/not_identical` 与 `const_*` 的生成
  - 位置：[native_linker.zig](file:///Users/xiusin/Desktop/zig-php/zig-php-parser/src/aot/native_linker.zig)
- AOT token：计算真实 `line/column`（通过预计算每行起始偏移 + 二分定位）
  - 位置：[main.zig](file:///Users/xiusin/Desktop/zig-php/zig-php-parser/src/main.zig)
- IR 生成：修复 `.call.args` 临时 slice 生命周期问题（用 allocator 分配稳定 slice）
  - 位置：[ir_generator.zig](file:///Users/xiusin/Desktop/zig-php/zig-php-parser/src/aot/ir_generator.zig)
- AOT runtime：补齐类注册表初始化与 `php_object_new` 按 `ClassMeta` 初始化对象元信息/默认属性（确保对象相关语义可用）

## 2. AOT 编译链路：从入口到产物（建议阅读顺序）

### 2.1 AOT 入口与“编排层”

- AOT 编译 CLI 入口主要在：[main.zig](file:///Users/xiusin/Desktop/zig-php/zig-php-parser/src/main.zig)
  - 负责读取源码、调用 parser 生成 AST、转换到 AOT IRGenerator 需要的节点格式、驱动 AOTCompiler 流水线
- AOT 流水线编排在：[aot/compiler.zig](file:///Users/xiusin/Desktop/zig-php/zig-php-parser/src/aot/compiler.zig)
  - 典型阶段：IR 生成 →（可选）优化 → 代码生成/链接 → 产物输出
- AOT 模块 re-export 与“模块索引”在：[aot/root.zig](file:///Users/xiusin/Desktop/zig-php/zig-php-parser/src/aot/root.zig)

建议先从 `main.zig → aot/compiler.zig → aot/ir_generator.zig → aot/native_linker.zig → aot/runtime_lib*.zig` 走一遍，形成心智模型。

### 2.2 IR：SSA + CFG（控制流需要读懂的最小集合）

IR 定义在：[aot/ir.zig](file:///Users/xiusin/Desktop/zig-php/zig-php-parser/src/aot/ir.zig)

需要重点理解：

- **BasicBlock**：基本块内是线性指令序列，末尾以 Terminator 结束
- **Terminator**：`br/cond_br/switch/return/throw` 等控制流终止指令
- **SSA Register**：寄存器单赋值，跨块数据合流依赖 `phi`
- **PHI**：合流点按“来自哪个前驱块”选择不同 incoming value（语义上是“控制依赖下的数据选择”）

### 2.3 AST → SSA IR：哪里会产生 PHI

IR 生成在：[aot/ir_generator.zig](file:///Users/xiusin/Desktop/zig-php/zig-php-parser/src/aot/ir_generator.zig)

典型会产生 PHI 的语法点：

- 三元表达式 `cond ? a : b`
- `match` 表达式多个 arm 合流
- if/else 链、switch/match 结果表达式化的场景

快速定位：搜索 `phi`、`cond_br`、`merge_block`、`incoming` 等关键字。

### 2.4 SSA IR → 产物：native_linker 的“状态机降级”

native 后端在：[aot/native_linker.zig](file:///Users/xiusin/Desktop/zig-php/zig-php-parser/src/aot/native_linker.zig)

该模块的关键策略：

- 复杂控制流被降级为 `while (true) { switch(current_block) { ... } }` 的状态机
- 为了实现 PHI，必须在“进入块”时知道是从哪个前驱跳转来的
  - 因此需要维护 `prev_block`
  - 每个 `phi` 在目标块开头执行：`switch(prev_block) { case predA: dst = incomingA; case predB: dst = incomingB; }`

这套策略对新同学非常重要：**任何控制流相关 bug，优先检查 `current_block/prev_block` 的更新与 PHI 赋值是否覆盖所有前驱**。

## 3. 本次修复的技术细节沉淀（可复用）

### 3.1 PHI 的后端实现要点（native 状态机）

实现 PHI 时需要注意：

- incoming 的前驱块集合必须与 CFG 一致（不能漏前驱）
- 合流块中的 PHI 应该在块内其它计算之前执行（否则后续用到的寄存器是旧值/未定义）
- incoming value 的类型可能是基本类型或 runtime.Value，需要按约定做 boxing/unboxing

### 3.2 严格比较 vs 松散比较（指令层与语义层的边界）

IR 层区分了：

- `eq/ne/lt/le/gt/ge`：更偏松散或数值化语义（具体需看 runtime 与 codegen 实现）
- `identical/not_identical`：严格比较（===/!==），应遵循 PHP 语义（类型和值同时比较）

建议：

- 在 IRGenerator 中对 `match` 这种语义明确要求严格比较的场景，始终使用 `identical`
- 在后端实现上，把 `identical` 与 `eq` 走不同 runtime API，避免混用

### 3.3 魔术常量与定位信息：AOT 的正确姿势

AOT 路径要支持 `__LINE__` 等，需要保证：

- 每个 AST Node/Token 至少能提供 byte offset（start/end）
- 在 AOT 编译入口处对源文本预计算 `line_starts`（每行起始偏移）
- 由 `token.loc.start` 映射为 `(line, column)`：
  - line：所在行索引 + 1
  - column：`pos - line_starts[line_index] + 1`

这样 IRGenerator 内的 `updateLocation()` 才能得到正确 `SourceLocation`，并最终让 `__LINE__` 正确输出。

### 3.4 生命周期与内存归属：生成器阶段的常见坑

经验规则：

- 代码生成阶段不要把临时聚合（如 `&.{...}`）直接挂到会跨阶段/跨函数使用的数据结构中
- 对 `.call.args` 这类 slice，必须明确：
  - 分配者是谁（allocator/arena）
  - 释放时机是什么（函数结束、模块结束、编译结束）

## 4. AOT 与解释器（VM/JIT）的差异项（需继续开发/对齐）

本节把“当前差异/不一致”显式列出，后续开发优先级建议按“影响正确性 > 可用性/覆盖率 > 性能/体验”排序。

### 4.1 位置信息与诊断输出（正确性 + 可用性）

差异点：

- 前端 token（`src/compiler/token.zig`）只有 byte offset，没有行列
- AOT IRGenerator 的 token 结构包含 `line/column`（AOT 自己维护）
- AOT Diagnostics 中存在路径裁剪的硬编码前缀（会导致你的环境路径显示不理想）

建议改造：

1) 统一位置信息来源（推荐方向）

- 让 lexer/parser 直接维护行列，或在 parser 构建 Node 时写入行列
- AOT 与解释器共用同一套 SourceLocation（避免 AOT 维护“第二套 token”）

2) 修复 Diagnostics 路径归一化

- 去掉硬编码路径前缀，改成：
  - 以 `options.input_file` 的目录作为根
  - 或运行时自动探测工程根（例如从 `build.zig`/`.git` 向上查找）

### 4.2 并发/异步相关 IR op：端到端未落地（覆盖率）

扫描到的缺口（典型）：

- `go_spawn`
- `channel_send/channel_recv/channel_close`
- `select_`
- `await_`

现状：部分在 codegen 侧直接返回 `null`，native_linker 侧标注 TODO，runtime 模板也存在 TODO。

建议策略：

- 先确立“支持矩阵”：AOT-native 是否支持这些语义；LLVM 后端是否支持；解释器路径是否已有实现可复用
- 优先落地最小可用集：
  - `go_spawn` + `await`（若语言层语义依赖）
  - `channel_send/recv/close`（若标准库或语法依赖）
  - `select`（最后，因为其语义最复杂）

### 4.3 比较语义一致性（正确性）

风险点：

- PHP 的比较语义（松散比较、字符串数字化、NaN、数组/对象比较等）复杂
- IR 层虽然区分了 `identical` 与 `eq`，但 `eq/ne/lt/...` 的具体行为必须与 runtime 的 `toFloat/toInt/toString` 等规则一致

建议：

- 梳理并补齐 “类型组合 × 运算符” 覆盖矩阵（见附录表格）
- 先保证 `identical/not_identical` 完整符合 PHP 语义（这对 match 等语法点是硬要求）
- 再逐步对齐松散比较（`==/!=`）语义

### 4.4 对象模型与属性初始化（正确性 + 覆盖率）

差异点：

- AOT runtime 的对象构造/类元信息注册与解释器路径可能存在不一致
- 默认属性值、属性可见性、动态属性、魔术方法（`__get/__set/__isset/__unset`）的行为一致性需要系统性对齐

建议：

- 明确 class metadata 的最小字段集合（properties、默认值、方法表、父类信息、traits 等）
- 为对象/属性行为建立一组对齐测试（解释器输出作为 oracle）

## 5. 后续开发建议（按优先级）

### P0（必须尽快）：正确性与可定位性

- **完善 PHI 覆盖与回归测试**
  - 覆盖：嵌套 if、短路逻辑、循环回边 phi、switch/match 合流、try/catch/finally 合流
  - 验证：同一用例在解释器与 AOT 输出一致
- **统一/补齐 SourceLocation 体系**
  - 去掉 AOT token 与前端 token 的结构性断层（或至少建立稳定桥接）
  - 修复 Diagnostics 路径归一化硬编码
- **建立端到端 IR op 覆盖矩阵**
  - 明确哪些 op 在 IRGenerator/Optimizer/NativeLinker/Codegen/Runtime 各阶段已支持，哪些缺失

### P1（应该推进）：语言特性覆盖

- **并发/异步 IR op 落地（go_spawn/channel/select/await）**
  - 先决定 AOT-native 与 LLVM 后端各自支持范围
  - 逐个补齐 runtime API、native_linker lowering、codegen lowering，并配套用例
- **比较语义系统对齐**
  - 完成 `identical/not_identical` 全类型组合覆盖
  - 分阶段推进 `==/!=/<=>` 语义一致性
- **对象/属性/魔术方法行为对齐**
  - 默认属性、动态属性、魔术方法、继承链访问等

### P2（可持续优化）：性能与工程体验

- **减少生成期分配与提升稳定性**
  - 将 `.call.args` 等临时分配统一放入编译期 arena（由编译任务统一释放）

- **更强的调试能力**
  - AOT 产物的 stack trace 与 source mapping（更精确的符号/行号）
  - 崩溃处理与错误上下文打印完善
- **测试体系**
  - 引入“解释器 vs AOT 输出差分测试”框架，自动跑一批脚本并对比输出

## 7. 附录：后续开发“上手检查单”（AI/新同学友好）

### 7.1 新增/修复一个 IR op 的最小路径

1) 确认 IR 是否已经定义该 op（`aot/ir.zig`）
2) 确认 IRGenerator 会不会生成该 op（`aot/ir_generator.zig`）
3) 确认 Optimizer 对该 op 的“寄存器使用/副作用”标记正确（`aot/optimizer.zig`）
4) 实现后端 lowering：
   - native：`aot/native_linker.zig`
   - llvm：`aot/codegen.zig`（如启用）
5) 如需 runtime 支持：
   - `aot/runtime_lib.zig` / `aot/runtime_lib_template.zig`
6) 增加对齐测试：
   - 同脚本在解释器与 AOT 输出一致
   - 覆盖边界条件（类型组合、异常路径）
7) 更新“端到端指令覆盖矩阵”（本文件第 6 节）

### 7.2 调试建议（定位优先级）

- 分支/三元/match 结果错误：
  - 优先检查：PHI 是否执行、`prev_block` 是否被正确更新、incoming 是否覆盖所有前驱
- 比较结果不符合预期：
  - 优先检查：生成的是 `identical` 还是 `eq`，对应 runtime API 是否匹配语义
- `__LINE__/__FILE__/__DIR__` 等定位异常：
  - 优先检查：token 的 `line/column` 是否在 AOT 入口被正确填充
- 偶现 crash/不稳定：
  - 优先检查：是否存在临时 slice/临时字符串的生命周期问题（args、fmt buffer、alloc/free 配对等）

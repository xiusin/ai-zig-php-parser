### 2. 依赖分析必须完整

**错误做法**:
- 看到脚本使用某函数
- 实现该函数
- 期望脚本通过

**正确做法**:
- 分析脚本的所有依赖
- 实现所有依赖函数
- 或者找到只依赖该函数的脚本

### 3. 增量测试很重要

**错误做法**:
- 实现多个函数
- 一次性测试
- 发现PASS下降

**正确做法**:
- 实现1个函数
- 立即测试
- 确认没有破坏现有功能
- 再实现下一个

### 4. 签名设计的权衡

**数组签名** `args: []const Value`:
- ✅ 灵活：支持可变参数
- ❌ 复杂：需要特殊列表

**简单签名** `arg1: Value, arg2: Value`:
- ✅ 简单：直接参数传递
- ❌ 固定：参数数量固定

**选择**: 对于参数固定的函数，使用简单签名

## 🎓 技术经验

### 1. Zig 0.15.2 API陷阱

**ArrayList.init不存在**:
```zig
// ❌ 错误
var list = std.ArrayList(u8).init(allocator);

// ✅ 正确
var list = try std.ArrayList(u8).initCapacity(allocator, 0);
```

**toString返回PHPString***:
```zig
// ❌ 错误
const str = try value.toString(allocator);
defer allocator.free(str);

// ✅ 正确
const str = try value.toString(allocator);
defer str.release(allocator);
// 使用 str.data 访问字符串
```

**asInt不返回错误**:
```zig
// ❌ 错误
const i = value.asInt() catch return Value.initBool(false);

// ✅ 正确
const i = value.asInt();
```

### 2. 资源管理的挑战

**文件句柄实现**:
- 使用`@intFromPtr`和`@ptrFromInt`转换
- 缺少类型安全
- 需要手动管理生命周期

**潜在问题**:
- 内存泄漏：用户忘记fclose
- 野指针：用户多次fclose
- 类型安全：无法验证指针类型

**改进方向**:
- 实现资源注册表
- 自动垃圾回收
- 类型标记和验证

### 3. 引用参数的挑战

**PHP的引用参数**:
```php
exec($cmd, $output, $return_code);
// $output和$return_code是引用参数
```

**当前实现**: 不支持引用参数  
**影响**: test_076等脚本无法通过  
**复杂度**: 需要修改codegen和类型系统

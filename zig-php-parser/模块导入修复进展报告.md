## 🎯 问题描述

Zig 0.15.2 不推荐使用 `../` 进行跨目录导入，建议使用模块系统或其他方式。项目中有 30+ 个文件使用了 `../` 导入，导致编译时出现警告（但不影响功能）。

---

## 🔧 尝试的解决方案

### 方案 1：创建统一的根导入文件 ❌

**实施**:
- 创建了 `src/root.zig` 文件，导出所有主要模块
- 更新了部分文件使用 `@import("root")` 导入

**问题**:
- 在测试环境中，`@import("root")` 指向测试运行器，而不是 `src/root.zig`
- 导致测试编译失败

### 方案 2：创建本地导入桥接文件 ❌

**实施**:
- 在 `src/jit/` 目录创建了 `imports.zig` 桥接文件
- 更新了 JIT 模块的文件使用本地导入

**问题**:
- 桥接文件内部仍然使用 `../` 导入
- 问题没有真正解决，只是转移了

### 方案 3：使用 build.zig 模块系统 ⏳

**建议**:
在 `build.zig` 中定义模块，然后在代码中使用模块名导入：

```zig
// build.zig
const compiler_mod = b.addModule("compiler", .{
    .root_source_file = b.path("src/compiler/ast.zig"),
});

const runtime_mod = b.addModule("runtime", .{
    .root_source_file = b.path("src/runtime/types.zig"),
});

// 在所有测试和可执行文件中添加模块
exe.root_module.addImport("compiler", compiler_mod);
exe.root_module.addImport("runtime", runtime_mod);

// 在代码中使用
const ast = @import("compiler").ast;
const Value = @import("runtime").Value;
```

**优点**:
- 符合 Zig 0.15.2 推荐的做法
- 在测试环境中也能正常工作
- 模块边界清晰

**缺点**:
- 需要大量修改 `build.zig`
- 需要更新所有使用跨目录导入的文件（30+ 个）
- 工作量较大（估计 2-3 小时）

### 编译警告 vs 编译错误

- ✅ **大部分 `../` 导入只产生警告，不影响编译和功能**

- ✅ 111/111 测试通过（100% 通过率）
- ⚠️ 有编译警告，但不影响功能
- ❌ 部分测试文件编译失败（由于导入问题）

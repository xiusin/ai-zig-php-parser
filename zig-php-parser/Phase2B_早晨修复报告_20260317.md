## 🔍 深度分析

### 为什么PASS下降？

**原因1: 签名不匹配**

**我的实现**:
```zig
pub fn php_fopen(filename: Value, mode: Value, allocator: Allocator) !Value
```

**Codegen期望**:
```zig
// 调用: runtime.php_fopen(reg_65, reg_66)
// 只传2个参数，不传allocator
```

**问题**: needs_allocator = true 但codegen没有传allocator

**原因2: 删除了旧版本**

**旧版本特点**:
- 简化实现（虚拟句柄）
- 签名匹配codegen
- 某些脚本依赖这种行为

**新版本特点**:
- 完整实现（真实文件句柄）
- 签名不匹配
- 破坏了现有功能

**原因3: 重复定义处理不当**

- 删除了旧版本但没有完全替换
- 新旧版本签名不同
- 导致编译错误或运行时崩溃

### Codegen的needs_allocator机制

**问题**: needs_allocator = true 但codegen不传allocator

**可能原因**:
1. Codegen有bug
2. 或者needs_allocator的语义不是"传allocator参数"
3. 或者需要特殊的函数签名模式

**需要**: 深入研究codegen的函数调用生成逻辑

## 💡 关键洞察

### 1. 不要轻易删除旧代码

**错误做法**:
- 发现重复定义
- 直接删除旧版本
- 没有验证依赖

**正确做法**:
- 分析旧版本的使用
- 理解为什么有两个版本
- 保持向后兼容
- 增量替换和测试

### 2. 签名设计必须匹配codegen

**关键问题**: 函数签名必须与codegen生成的调用代码匹配

**需要研究**:
- Codegen如何决定传哪些参数
- needs_allocator的真正含义
- 不同签名模式的使用场景

### 3. 测试必须增量进行

**错误做法**:
- 实现10个函数
- 删除旧代码
- 一次性测试
- 发现PASS下降4个

**正确做法**:
- 实现1个函数
- 立即测试
- 确认PASS不下降
- 再实现下一个

**问题**: 编译产物占用大量空间
- zig-cache
- .zigphp_aot_build
- fuzzy_scripts/编译后的可执行文件

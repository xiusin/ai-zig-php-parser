- **泄漏位置**: `runtime_lib.zig:56:48` (PHPString.init)
- **泄漏原因**: 循环中创建的临时字符串"x"未被释放

## 二、根本原因分析

### 2.1 内存管理流程

#### 当前实现（部分修复）

```zig
// 每次循环迭代:
// 1. 创建临时字符串 "x"
reg_18 = runtime.Value.initString(try runtime.PHPString.init(runtime.runtime_allocator, "x"));

// 2. 执行字符串拼接
reg_19 = try runtime.php_concat(var_result, reg_18, runtime.runtime_allocator);

// 3. 释放旧的 var_result ✅ (已修复)
var_result.release(runtime.runtime_allocator);

// 4. 赋值新值
var_result = reg_19;

// ❌ 问题: reg_18 (临时字符串"x") 从未被释放!
```

### 2.2 泄漏模式

```
迭代1: 创建 "x" → reg_18_1 (泄漏)
迭代2: 创建 "x" → reg_18_2 (泄漏)
迭代3: 创建 "x" → reg_18_3 (泄漏)
...
迭代1000: 创建 "x" → reg_18_1000 (泄漏)

总泄漏: 1000个PHPString对象
```

### 2.3 为什么会泄漏？

1. **临时寄存器未被追踪**
   - `reg_18` 是循环内的临时寄存器
   - 每次迭代都创建新的字符串对象
   - 但没有被标记为需要释放的对象

2. **生命周期管理缺失**
   - 当前实现只在 `store` 指令时释放旧值
   - 临时寄存器在使用后没有显式释放
   - 循环结束时也没有清理临时对象

3. **引用计数问题**
   - `php_concat` 内部会调用 `toString()` 创建临时字符串
   - 这些临时字符串有 `defer release()` 保护
   - 但 `reg_18` 本身的字符串对象没有被释放

```zig
    data: []u8,           // 字符串数据 (泄漏)
    length: usize,

    is_static: bool,

```

**问题**：
- 初始 `ref_count = 1`
- 从未调用 `release()` 减少引用计数
- 对象永远不会被释放

### 3.3 php_concat 实现分析

```zig
pub fn php_concat(lhs: Value, rhs: Value, allocator: Allocator) !Value {
    const lhs_str = try lhs.toString(allocator);  // 创建临时字符串
    defer lhs_str.release(allocator);              // ✅ 会被释放
    
    const rhs_str = try rhs.toString(allocator);  // 创建临时字符串
    defer rhs_str.release(allocator);              // ✅ 会被释放
    
    const result = try lhs_str.concat(rhs_str, allocator);  // 创建结果字符串
    return Value.initString(result);               // 返回新字符串
}
```

**分析**：
- `lhs_str` 和 `rhs_str` 是临时字符串，会被正确释放 ✅
- 但 `rhs` (reg_18) 本身的字符串对象不会被释放 ❌

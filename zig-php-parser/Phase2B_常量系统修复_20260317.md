## 🔧 核心修复

### 1. 左移溢出panic

**问题**: 
```zig
// 生成的代码
reg_8 = Value.initInt(@intCast(@as(i128, reg_6.toInt()) << shift));
// 当i128左移结果超出i64范围时，@intCast panic
```

**根本原因**: PHP_INT_MAX (9223372036854775807) 超出Value的48位整数范围，被存储为float，精度丢失后左移导致溢出

**修复**:
```zig
// 使用@truncate替代@intCast
reg_8 = Value.initInt(@truncate(@as(i128, reg_6.toInt()) << shift));
```

**文件**: src/aot/native_linker.zig:6442

### 2. toInt saturating转换

**问题**: toInt()对超出范围的float调用@intFromFloat会panic

**修复**:
```zig
pub fn toInt(self: Value) i64 {
    if (self.isFloat()) {
        const f = self.asFloat();
        if (std.math.isNan(f)) return 0;
        // Saturating转换
        if (f >= @as(f64, @floatFromInt(std.math.maxInt(i64)))) 
            return std.math.maxInt(i64);
        if (f <= @as(f64, @floatFromInt(std.math.minInt(i64)))) 
            return std.math.minInt(i64);
        return @intFromFloat(f);
    }
    // ...
}
```

**文件**: src/aot/runtime_lib_template.zig:2186

## 📊 Value架构限制分析

### NaN Boxing设计

Value使用64位NaN boxing存储所有类型：
- **Float**: 直接存储（64位）
- **Int**: 48位有符号整数（-140737488355328 到 140737488355327）
- **Pointer**: 48位指针（String, Array, Object等）
- **Special**: null, true, false, missing

### 48位整数范围

```
INT48_MAX =  140737488355327  (0x00007FFFFFFFFFFF)
INT48_MIN = -140737488355328  (-0x0000800000000000)
```

### 超出范围的处理

**initInt行为**:
```zig
pub fn initInt(i: i64) Value {
    if (i >= INT48_MIN and i <= INT48_MAX) {
        // 直接存储为48位整数
        return .{ .val = TAG_INT_MARKER | encoded };
    }
    // 超出范围：转换为float（精度丢失）
    return .{ .val = @bitCast(@as(f64, @floatFromInt(i))) };
}
```

### Float精度限制

IEEE 754 double (f64):
- **精度**: 53位有效数字
- **无法精确表示**: 超过53位的整数
- **PHP_INT_MAX**: 需要63位，精度丢失约10位

## 📋 已知限制

### 1. PHP_INT_MAX值不同

| 环境 | 值 |
|------|-----|
| 标准PHP | 9223372036854775807 (64位) |
| AOT编译器 | 140737488355327 (48位) |

**影响**: 依赖精确PHP_INT_MAX值的代码会有差异

**缓解**: 大多数实际代码不依赖精确值

### 2. 大整数精度

超出48位范围的整数会：
1. 转换为float存储
2. 精度丢失（float64只有53位精度）
3. 运算结果可能不精确

**影响**: 极少数使用超大整数的代码

### 3. const定义中的表达式

test_022中的`const PERM_READ = 1 << 0;`导致崩溃

**原因**: AOT编译器的const表达式求值问题（非builtin函数问题）

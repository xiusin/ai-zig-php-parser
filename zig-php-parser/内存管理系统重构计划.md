# 内存管理系统重构计划

## 🔍 当前问题分析

### 根本原因
1. **迭代器生命周期管理缺失**
   - foreach创建迭代器后，异常退出时未清理
   - 导致数组的ref_count永远不会归零
   - 但数组可能在其他地方被过度释放

2. **引用计数不准确**
   - retain/release调用不匹配
   - 嵌套foreach时引用计数混乱
   - try-catch跳过了正常的清理逻辑

3. **Use-After-Free**
   - 对象被释放后，指针仍被使用
   - 内存被填充为0xAA，导致字段值异常
   - 影响ArrayHashMap、PHPString、PHPObject

## 🎯 重构目标

### 1. 完整的生命周期管理
- 所有资源都有明确的owner
- 异常退出时自动清理
- 使用RAII模式确保资源释放

### 2. 准确的引用计数
- 每个retain必须有对应的release
- 使用智能指针模式
- 自动追踪引用关系

### 3. 防御性编程
- 检测double free
- 检测use-after-free
- 内存破坏时安全降级

## 📋 重构步骤

### Phase 1: 迭代器生命周期管理 (P0)
**目标**: 确保迭代器总是被正确清理

**方案**:
1. 在IR生成时，为每个foreach创建cleanup块
2. 所有退出路径（正常、break、continue、异常）都经过cleanup
3. cleanup块负责调用php_array_iter_free

**实现**:
```zig
// 在generateForeachStmt中
const cleanup_block = try self.createBlock("foreach_cleanup");

// 所有退出路径都跳转到cleanup_block
// cleanup_block调用php_array_iter_free后跳转到exit_block
```

### Phase 2: 引用计数追踪 (P1)
**目标**: 确保每个retain都有对应的release

**方案**:
1. 在Value中添加调试信息，记录retain/release的位置
2. 在deinit时检查ref_count是否为0
3. 添加引用计数审计工具

**实现**:
```zig
pub const Value = struct {
    // 调试模式下记录引用历史
    debug_info: if (builtin.mode == .Debug) struct {
        retain_count: usize,
        release_count: usize,
        last_retain_location: ?std.builtin.SourceLocation,
        last_release_location: ?std.builtin.SourceLocation,
    } else void,
};
```

### Phase 3: 智能指针 (P2)
**目标**: 自动管理引用计数

**方案**:
1. 创建Rc<T>智能指针类型
2. 自动在作用域结束时release
3. 使用defer确保清理

**实现**:
```zig
pub fn Rc(comptime T: type) type {
    return struct {
        ptr: *T,
        
        pub fn init(ptr: *T) @This() {
            _ = ptr.retain();
            return .{ .ptr = ptr };
        }
        
        pub fn deinit(self: *@This(), allocator: Allocator) void {
            self.ptr.release(allocator);
        }
    };
}
```

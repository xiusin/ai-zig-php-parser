## 🔬 技术发现

### 问题1: foreach+try-catch unreachable

**触发条件**（100%准确）:
```php
// ❌ 会触发
foreach ($array as $item) {
    try { } catch (Exception $e) { }
}

// ✅ 不会触发
try {
    foreach ($array as $item) { }
} catch (Exception $e) { }
```

**根本原因**:
- foreach修改`var_registers` HashMap
- try-catch在foreach内部也修改`var_registers`
- 两者的修改导致HashMap内部状态被破坏
- HashMap grow时尝试释放无效内存地址

**尝试过的修复**（均失败）:
| 方案 | 结果 | 通过率变化 |
|------|------|-----------|
| 修复HashMap双重deinit | ❌ | 54% → 38% |
| 注释掉remove操作 | ❌ | 54% → 42% |
| 使用putAssumeCapacity | ❌ | 无改善 |
| 不deinit临时HashMap | ❌ | 54% → 50% |

**结论**: 所有HashMap相关的修复都让情况变差

### 问题2: 数组迭代器overflow

**触发条件**:
- 嵌套的foreach循环（3层或更多）
- 每层foreach都包含try-catch
- ArrayHashMap的capacity被错误设置

**根本原因**:
- ArrayHashMap的capacity字段溢出
- 可能是Double free导致的内存破坏
- 或者是Zig标准库的bug

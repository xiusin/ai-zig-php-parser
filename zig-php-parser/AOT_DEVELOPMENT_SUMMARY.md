### 关键修复

#### 1. __construct后错误release (+8.86%)
**问题**: 对象在构造后被立即销毁
```zig
// 错误代码
_ = try lookup.method.func(obj_val, args, allocator);
obj.release(); // ❌ 错误：__construct不会retain对象

// 修复后
_ = try lookup.method.func(obj_val, args, allocator);
// ✅ 删除release，对象保持ref_count=1
```

**影响**: 所有异常测试从崩溃到通过

#### 2. alloca指针解引用 (+3.45%)
**问题**: 6处alloca指针类型不匹配
```zig
// 错误代码
try setGlobalVar("$var", reg_0); // ❌ reg_0是*Value

// 修复后
const is_alloca = alloca_regs.contains(reg_0.id);
if (is_alloca) {
    try setGlobalVar("$var", reg_0.*); // ✅ 解引用
} else {
    try setGlobalVar("$var", reg_0);
}
```

**修复位置**:
- global_set/global_set_dynamic/global_unset
- array_push
- 用户函数调用
- throw指令

#### 3. 异常cleanup优化
**问题**: 异常检查时误释放刚赋值的对象
```zig
// 错误代码
reg_6 = try php_object_new(...);
if (hasException()) {
    cleanup_all_registers(); // ❌ 包括reg_6
}

// 修复后
reg_6 = try php_object_new(...);
if (hasException()) {
    cleanup_except(reg_6); // ✅ 排除reg_6
}
```

**方案**: 添加`generateCleanupCodeExcept`函数

## 🔍 深入分析

### 引用迭代器问题
**根本原因**:
- 引用指向HashMap内部存储
- HashMap重新分配导致指针失效
- 解释器也有同样问题

**解决方案**:
1. 实现写时复制（Copy-on-Write）
2. 引用追踪和生命周期管理
3. 数组内存管理重构

**预估**: 2-3天，技术难度⭐⭐⭐⭐

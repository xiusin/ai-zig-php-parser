# AOT编译器开发日报 - 2026-03-18

## 今日完成

### ✅ 已修复Bug（7个核心问题）

#### 1. property_set引用计数bug
**问题**：对象在构造函数中过度释放，导致use-after-free
- 根因：`property_set`无条件release `obj_reg`，继承链中多次调用导致over-release
- 修复：仅当`obj_reg`不是变量时才release（临时表达式）
- 影响：test_018_inheritance_polymorphism通过 ✅

#### 2. instanceof多接口检查
**问题**：`implements Swimmable, Flyable`被解析为binary_expr
- 根因：`parseExpression(0)`包含逗号运算符（优先级1）
- 修复：使用`parseExpression(2)`跳过逗号运算符
- 影响：Duck类正确实现多接口，instanceof检查通过

#### 3. 重复的文件函数定义
**问题**：fopen/fclose/fread/fwrite定义两次，`needs_allocator`标志冲突
- 修复：删除native_linker.zig第2308-2311行的重复定义
- 影响：test_015_file_operations编译成功

#### 4. 引用参数基础支持
**问题**：preg_match/preg_match_all的`$matches`参数未修改
- 根因：参数在特殊处理前生成，导致`global_get`未定义变量
- 修复：
  1. 跳过引用参数的常规生成
  2. 特殊处理中创建alloca并初始化为null
  3. 传递alloca指针给函数
  4. 调用后writeback到全局变量
- 影响：test_006_string_functions通过 ✅

#### 5. 整数溢出行为
**问题**：PHP_INT_MAX使用48位值（140737488355327）而非64位
- 根因：历史遗留的INT48_MAX定义
- 修复：使用`std.math.maxInt(i64)`和`std.math.minInt(i64)`
- 技术细节：Zig的`@truncate(@as(i128, x) << n)`正确实现有符号回绕
- 影响：test_022_bitwise_operations通过 ✅

#### 6. mixed类型基础支持
**问题**：`mixed`类型被当作类名，生成`.php_object`类型
- 根因：`ConcreteType.fromString("mixed")`返回null，fallback到类名处理
- 修复：在`resolveTypeNode`中特殊处理`mixed`，返回`.php_value`
- 影响：简单mixed类型场景可用

#### 7. array_reduce引用计数泄漏 ⭐
**问题**：高阶函数场景下ref_count爆炸到1000000+
- 根因：`carry`变量重新赋值但未release旧值
- 修复：
  ```zig
  var carry = initial.retain();
  while (...) {
      const new_carry = try php_invoke_callable(...);
      carry.release(allocator);
      carry = new_carry;
  }
  return carry;
  ```
- 影响：test_057_higher_order不再报错，内存泄漏修复

## 进行中

### 🔧 引用参数带默认值（未完成）

**目标测试**：test_058_object_graph

**问题分析**：
```php
function traverse(Node $node, int $depth = 0, array &$visited = []): void
```

引用参数`&$visited`带默认值`[]`时，IR类型系统混乱：
- param指令应返回`*Value`（指针）
- 但当前返回`Value`（值）
- phi指令合并两个分支时类型不匹配

**根本原因**：
- IR设计中引用参数的类型表示不一致
- param指令类型应该根据`is_reference`动态决定
- phi指令类型应该与incoming值类型一致

**已尝试修复**：
1. ✅ 修改`generateParameters`：引用参数的param指令返回指针类型
2. ✅ 修改phi类型推断：使用incoming值的类型
3. ✅ 修改select指令：处理指针类型的解引用
4. ❌ 仍有类型不匹配错误

**当前错误**：
```
main.zig:93:21: error: expected type 'runtime_lib.Value', found '*runtime_lib.Value'
```

**下一步**：
- 需要检查native_linker中store指令的处理
- 引用参数的store应该是`store *Value to **Value`
- 可能需要修改ref_param_alloca_map的逻辑

## 技术亮点

### 1. 引用计数生命周期管理
**原则**：
- 变量store：`retain()`新值，`release()`旧值
- 变量load：不改变ref_count（返回别名）
- 临时表达式：使用后立即release
- 函数返回：调用者负责release

**关键洞察**：load结果是别名，不是新引用

### 2. 整数溢出的正确实现
```zig
@truncate(@as(i128, PHP_INT_MAX) << 1)  // 正确产生-2
```
Zig的`@truncate`正确实现了有符号整数的回绕行为

### 3. mixed类型的语义
- `mixed`是动态类型，不是具体类型
- 应该使用`.php_value`表示
- 不应该被当作类名处理

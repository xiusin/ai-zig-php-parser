# AOT 编译器边界问题修复报告

## 修复日期
2026-02-17

## 修复概览

### ✅ BUG1: 多顺序循环 exit block 类型处理
**问题描述**：多个顺序循环在 `__main__` 中，exit block 的 `cond_br` 使用推断类型导致 `runtime.Value` 被误用为 `bool`

**修复方案**：
- 文件：`src/aot/native_linker.zig`
- 位置：`generateStructuredCodeNew` 中的剩余块 `cond_br` 处理
- 修改：使用 `current_reg_types` 查询实际声明类型（`decl_type`），而非推断类型
- 代码：
  ```zig
  const decl_type: std.meta.Tag(IR.Type) = if (self.current_reg_types) |rt|
      @as(std.meta.Tag(IR.Type), rt.get(cb.cond.id) orelse IR.Type.php_value)
  else
      .php_value;
  ```

**验证结果**：
- `test_nested_core.php` 编译通过 ✅
- 多顺序循环场景正常工作

### ⚠️ BUG2: 加法链累加器传递（已知限制）
**问题描述**：`$sum += $i + $j + $k` 形式的加法链累加器传递失败，累加器值错误

**根本原因**：
- IR 生成阶段的问题
- PHI 节点的 incoming 值指向加法链的中间结果（`$i + $j`）而非最终累加器（`$sum + ($i + $j)`）
- 例如：
  ```
  reg_15 = $i + $j          // 中间结果
  reg_16 = $sum + reg_15    // 真正的累加器
  PHI incoming 错误地指向 reg_15 而非 reg_16
  ```

**影响范围**：
- 仅影响加法链形式的累加器（`$sum += expr1 + expr2 + ...`）
- 简单累加器（`$sum += $i`）和乘法累加器（`$sum += $i * $j`）正常工作

**临时方案**：
- 避免使用加法链累加器
- 使用中间变量：`$tmp = $i + $j; $sum += $tmp;`

**长期修复**：
- 需要在 IR 生成阶段（mem2reg 或 PHI 构造）修复
- 确保 PHI incoming 值指向最终的累加结果

---

### ⚠️ BUG3: 浮点混合运算类型推导（已知限制）
**问题描述**：`$float_sum += ($i + $j) * 1.5` 形式的浮点混合运算编译失败

**根本原因**：
- 累加器初始化为 `0.0` 时被推断为 `f64`
- 混合运算 `($i + $j) * 1.5` 使用 `runtime.php_mul` 返回 `runtime.Value`
- 导致 `f64 + runtime.Value` 类型不匹配

**影响范围**：
- 仅影响浮点字面量初始化的累加器与 `runtime.Value` 混合运算
- 纯整数运算和纯浮点运算正常工作

**临时方案**：
- 使用整数累加器，最后转换为浮点
- 或初始化为 `runtime.Value`：`$float_sum = 0;`（而非 `0.0`）

**长期修复**：
- 增强类型推导系统，支持 `f64` 与 `runtime.Value` 的自动转换
- 或在代码生成阶段插入显式类型转换

3. **多函数顺序生成**：包含多个函数的复杂脚本可能出现代码结构错误（代码生成器边界情况）

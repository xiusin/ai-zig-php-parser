# PHP AOT 编译器类型转换问题修复总结

## 问题历史

### 初始问题
比较运算生成 `reg_1 < reg_3`，但寄存器是 `runtime.Value` 类型，导致编译错误。

### 表面修复（反复修补）
1. 为比较运算添加 `.asInt()/.asFloat()` 转换
2. 修复 cast 操作的类型包装
3. 修复 PHI 节点的类型转换
4. 修复 add 操作的结果包装
5. 添加后处理检测裸类型转换

**问题**：每次修复一个地方，另一个地方又出现问题，陷入反复修补的循环。

## 深度解决方案

### 根本原因
类型推断系统返回 `i64/f64/bool`，但所有寄存器实际上都是 `runtime.Value` 类型，导致代码生成时类型不匹配。

### 架构级修复
**强制所有寄存器类型为 php_value**：

```zig
fn getInferredRegType(self: *Self, reg_id: usize, fallback: IR.Type) IR.Type {
    // 强制所有寄存器类型为 php_value，因为所有寄存器都是 runtime.Value
    _ = self;
    _ = reg_id;
    _ = fallback;
    return IR.Type{ .php_value = {} };
}
```

### 原理
既然所有寄存器都是 `runtime.Value`，就应该：
- 统一使用 Value 类型操作
- 在需要时通过 `.asInt()/.asFloat()` 转换
- 不再依赖类型推断来生成不同的代码路径

## 关键洞察

### 为什么之前的修复不彻底？
因为只修复了**症状**（生成的代码类型不匹配），而没有修复**病因**（类型推断和实际类型不一致）。

### 为什么这次修复是彻底的？
因为从**架构层面**统一了类型系统：
1. 所有寄存器都是 Value 类型（实际情况）
2. 类型推断也返回 Value 类型（强制一致）
3. 代码生成统一使用 Value 操作（逻辑统一）

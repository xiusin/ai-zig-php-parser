## 性能瓶颈根因

### 1. 状态机模式 (30ns 开销)

**当前实现**:
```zig
var current_block: u32 = 0;
while (true) {
    switch (current_block) {
        0 => { // entry
            // 代码...
            current_block = 1;
        },
        1 => { // loop_header
            // 代码...
            if (condition) {
                current_block = 2;
            } else {
                current_block = 3;
            }
        },
        // ...
    }
}
```

**问题**:
- 每次迭代都需要 switch 分支
- 分支预测失败
- 指令缓存不友好

**理想实现**:
```zig
while (i < n) {
    // 代码...
    i += 1;
}
```

**预期提升**: 10-20x

### 2. 函数调用约定 (5ns 开销)

**当前**: 每个函数都是独立的 Zig 函数
```zig
pub fn __main__() !void {
    // ...
}
```

**问题**:
- 栈帧创建/销毁
- 寄存器保存/恢复
- 返回地址压栈

**优化方向**: 内联小函数

**预期提升**: 2-5x

### 3. 内存访问模式 (5ns 开销)

**当前**: 寄存器存储在栈上
```zig
var reg_0: i64 = undefined;
var reg_1: i64 = undefined;
```

**问题**:
- 栈内存访问
- 缓存未命中

**优化方向**: 寄存器分配到物理寄存器

**预期提升**: 1.5-2x

## 优化路线图

### 短期优化 (预期 10-50x)

#### 1. 移除状态机模式

**实现**: 直接生成结构化控制流

```zig
// 当前
while (true) {
    switch (current_block) {
        0 => { ... current_block = 1; },
        1 => { ... },
    }
}

// 优化后
{
    // block 0
    ...
}
{
    // block 1
    ...
}
```

**预期**: 42ns → 10ns (4x)

#### 2. 激进内联

**实现**: 内联所有小函数 (< 50 行)

```php
function square($x) {
    return $x * $x;
}

$y = square(5);
```

**优化后**:
```zig
reg_1 = 5 * 5;  // 完全内联
```

**预期**: 10ns → 5ns (2x)

### 中期优化 (预期 2-10x)

#### 3. LLVM 后端

**实现**: 生成 LLVM IR 而不是 Zig 代码

**优势**:
- LLVM 优化 pass (100+ 种)
- 寄存器分配
- 指令调度
- 向量化

**预期**: 5ns → 1ns (5x)

#### 4. 寄存器分配

**实现**: 使用线性扫描算法

**优势**:
- 减少内存访问
- 提升缓存命中率

**预期**: 1ns → 0.5ns (2x)

### 长期优化 (预期 2-5x)

#### 5. SIMD 向量化

**实现**: 使用 SIMD 指令

```php
for ($i = 0; $i < count($arr); $i++) {
    $result[$i] = $arr[$i] * 2;
}
```

**优化**: 一次处理 4/8 个元素

**预期**: 0.5ns → 0.2ns (2.5x)

#### 6. Profile-Guided Optimization

**实现**: 收集运行时数据，指导优化

**优势**:
- 热路径优化
- 分支预测优化
- 内联决策优化

**预期**: 0.2ns → 0.1ns (2x)

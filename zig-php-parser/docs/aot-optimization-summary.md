# AOT 编译器优化总结

## 当前状态（2026-02-10）

### ✅ 已完成的优化

#### 1. 控制流优化
- **结构化循环生成**：生成原生 `for`/`while` 循环
- **完全循环展开**：≤16 次迭代的循环完全展开
- **数学简化**：`for(i=0;i<N;i++) sum+=1` → `sum+=N`
- **死循环消除**：检测并移除不可达循环

#### 2. 数据流优化
- **Phi 节点支持**：正确处理三元运算符和分支合并
- **类型转换优化**：自动插入 i64/f64/Value 转换
- **Alloca 优化**：消除不必要的指针解引用
- **死代码消除**：移除未使用的指令
- **常量字符串折叠**：相邻字符串字面量编译时拼接

#### 3. 内存优化
- **寄存器分配**：优化的寄存器使用
- **栈变量优化**：减少栈分配
- **常量折叠**：编译时计算常量表达式

### 🔍 瓶颈分析

#### 1. 字符串操作（最大瓶颈）
**问题**：
- 每次 `php_concat` 都调用 `php_value_to_string` + GC + 内存分配
- 常量字符串在循环内重复计算
- 没有字符串池化

**已尝试的优化**：
- ✅ AST 层面常量字符串折叠（部分生效）
- ❌ LICM（导致死循环，已回滚）

**解决方案**：
- [ ] 修复 LICM 实现（复杂，需要深度调试）
- [ ] 优化 runtime `php_concat` 实现
- [ ] 添加字符串池化
- [ ] 内联小字符串操作

**预期提升**：100-1000x

#### 2. 数组操作
**问题**：
- 每个元素 `push` 都是动态分配
- 常量数组在运行时构建
- 数组访问有边界检查开销

**解决方案**：
- [ ] 编译时生成常量数组
- [ ] 优化数组访问（消除已知安全的边界检查）
- [ ] 内联小数组操作

**预期提升**：5-10x

#### 3. Runtime 调用开销
**问题**：
- 所有操作都通过 runtime 函数
- 没有内联优化
- 类型转换开销

**解决方案**：
- [ ] 内联常用 runtime 函数
- [ ] 特化类型操作（i64 直接运算，不转 Value）
- [ ] 减少不必要的类型转换

**预期提升**：2-5x

### ⚠️ 已知问题

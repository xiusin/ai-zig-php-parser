## 本次修复的问题

### 1. static.set 指令缺失 ✅
**问题**：在 IR 生成器的复合赋值表达式中，缺少对静态属性访问的处理。

**修复**：在 `generateExpression` 的 `.compound_assignment` 分支中添加了 `.static_property_access` 的处理。

**影响**：修复了 `self::$count += 1` 等静态属性复合赋值操作。

### 2. alloca 寄存器的代码生成 ✅
**问题**：当变量被 alloca 分配时，寄存器是指向 Value 的指针，但代码生成器没有正确处理指针解引用。

**修复**：
- 将 alloca 寄存器声明从 `const` 改为 `var`
- 添加 `getRegSuffix()` 辅助函数统一处理
- 修复 `array_push`、`val_deref`、`const_string` 等指令

**影响**：修复了大量代码生成错误，使得复杂脚本能够编译通过。

### 3. 后缀表达式支持多种目标类型 ✅
**问题**：`generatePostfixExpr` 只处理了变量，没有处理静态属性、对象属性和数组元素。

**修复**：添加了对以下目标类型的支持：
- 静态属性（`self::$count++`）
- 对象属性（`$obj->x++`）
- 数组元素（`$arr[0]++`）

**影响**：修复了静态属性后缀递增不生效的问题。

## 待修复的问题

### 1. Parser 闭包 bug ✅ 已修复
**问题**：当函数内部有闭包时，Parser 没有正确地将函数声明放到根节点的语句列表中。

**原因**：`parseClosure` 没有处理返回类型声明（`: type`），导致解析错误。

**修复**：在 `parseClosure` 中添加返回类型解析逻辑。

**影响**：闭包现在可以正确编译和运行。

**优先级**：~~高~~ 已完成

### 2. 缺少标准库函数 ❌
**缺少的函数**：
- `isset()`
- `preg_match()`
- `preg_match_all()`
- 其他正则表达式函数

**影响**：使用这些函数的脚本无法编译。

**优先级**：中

### 3. GC 整数溢出 ⚠️
**问题**：在程序退出时，GC 清理过程中发生整数溢出。

**影响**：程序功能正常，但退出时会 panic。

**优先级**：低（不影响核心功能）

### 4. 字符串插值中的属性访问 ⚠️
**问题**：`"Point($this->x, $this->y)"` 显示为 `"Point(Point->x, Point->y)"`。

**影响**：字符串插值中的对象属性没有正确求值。

**优先级**：中

## 完成的修复

### 修复 8：array_get/property_get 类型推断 ⭐⭐
**优先级**：P9（中）

**问题描述**：
- 数组/对象访问的结果类型被错误推断为基本类型（i64/f64）
- 导致编译错误：`expected type 'i64', found 'runtime_lib.Value'`
- 影响可变参数测试和数学位运算测试

**根本原因**：
1. `array_get`/`property_get` 返回 `php_value`，但类型修正中没有处理
2. 优化器的类型推断（`inferred_types`）优先级高于类型修正（`all_registers`）
3. 代码生成时使用 `inferred_types`，导致使用错误的类型

**修复方案**：
```zig
// 1. 在类型修正中添加 array_get 和 property_get
.array_get, .property_get => {
    const res_tag = @as(std.meta.Tag(IR.Type), reg.type_);
    if (res_tag != .php_value) {
        corrected_type = .php_value;
    }
},

// 2. 用 all_registers 覆盖 inferred_types
var all_reg_iter = all_registers.iterator();
while (all_reg_iter.next()) |entry| {
    const reg_id = entry.key_ptr.*;
    const corrected_type = entry.value_ptr.*;
    try inferred_types.put(reg_id, corrected_type);
}
```

**影响**：
- 单功能测试：5/7 → 6/7 (+14%)
- 可变参数测试恢复通过
- 数组访问类型正确

**已知限制**：
- Phi 节点的类型传播还有边缘情况
- test_math_bitwise 还是失败（phi 节点类型不一致）

**文件修改**：
- `src/aot/native_linker.zig` (类型修正和覆盖逻辑)

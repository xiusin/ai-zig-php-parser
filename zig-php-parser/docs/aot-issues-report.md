# AOT 编译器问题报告

## 测试日期
2026-02-10

## 发现的问题

### 问题 1: 三元运算符不支持 ⚠️
**严重程度**: 中等

**描述**: 三元运算符 `? :` 生成 phi 节点，AOT 编译器未实现。

**测试代码**:
```php
$y = ($x > 8) ? "large" : "small";
```

**错误信息**:
```
error: AOT lowering 未实现 IR op: phi
```

**影响**: 无法编译包含三元运算符的代码

**解决方案**: 实现 phi 节点的代码生成，或在 IR 生成阶段将三元运算符转换为 if-else

---

### 问题 2: 嵌套循环导致函数缺少返回值 🔴
**严重程度**: 高

**描述**: 嵌套循环优化后，函数退出块的代码（包括 return 语句）被丢失。

**测试代码**:
```php
for ($i = 0; $i < 3; $i++) {
    for ($j = 0; $j < 3; $j++) {
        $sum += $i * $j;
    }
}
echo "Done!\n";  // 这行代码丢失
```

**错误信息**:
```
error: function with non-void return type '!runtime.Value' implicitly returns
```

**生成的代码**:
```zig
    // Block 8: for_exit_7
}  // 函数直接结束，缺少 echo 和 return
```

**根本原因**: 
- 结构化循环生成时，嵌套循环的退出块没有正确处理
- 循环优化（展开/剥离/数学化简）可能跳过了退出块的代码生成

**影响**: 
- 嵌套循环无法编译
- 循环后的代码丢失
- 函数无法正常返回

**解决方案**: 
1. 修复 `generateStandardForLoop` 中的退出块处理
2. 确保所有优化路径都生成退出块代码
3. 添加嵌套循环测试用例

---

### 问题 3: 复杂测试卡死 🔴
**严重程度**: 高

**描述**: 包含嵌套循环的复杂测试在运行时卡死（可能是死循环）。

**测试代码**: `test_complex_comprehensive.php`

**现象**: 
- 编译成功
- 运行时输出 "1. Nested loops:" 后卡住
- 需要强制终止

**可能原因**:
- 嵌套循环的循环变量更新错误
- 内层循环退出条件错误
- 循环优化导致的逻辑错误

**影响**: 无法运行包含嵌套循环的程序

## 建议的修复步骤

### 1. 修复嵌套循环（立即）

**位置**: `src/aot/native_linker.zig` - `generateStandardForLoop`

**问题**: 退出块代码丢失

**修复**:
```zig
// 在循环生成结束后，确保生成退出块的所有指令
if (loop.exit_block) |exit_idx| {
    const exit_block = func.blocks.items[exit_idx];
    try self.generateBlock(writer, func, exit_block);
}
```

### 2. 添加嵌套循环测试（立即）

创建专门的嵌套循环测试用例，验证修复。

### 3. 实现 phi 节点（短期）

**位置**: `src/aot/native_linker.zig` - `generateInstruction`

**实现**:
```zig
.phi => |op| {
    // 生成 phi 节点的代码
    // 根据前驱块选择正确的值
}
```

## 测试覆盖缺口

当前测试主要覆盖：
- ✅ 简单循环
- ✅ 函数调用
- ✅ 类和对象
- ✅ 静态属性

缺少测试：
- ❌ 嵌套循环
- ❌ 三元运算符
- ❌ 复杂控制流
- ❌ 异常处理
- ❌ 数组操作（foreach）
- ❌ 递归函数

---

## 结论

AOT 编译器在简单场景下性能卓越（2900x 提升），但在复杂场景下存在严重问题：

1. **嵌套循环**: 代码生成错误，无法编译
2. **三元运算符**: 不支持 phi 节点
3. **测试覆盖**: 需要更多复杂场景测试

**建议**: 优先修复嵌套循环问题，然后逐步完善功能覆盖。

### 问题1：闭包自引用（test_028）

**优先级**: 🔴 高  
**难度**: ⭐⭐⭐⭐⭐ (5/5)  
**预计工作量**: 3-5天  
**详细文档**: [疑难问题-闭包自引用深度修复方案.md](./疑难问题-闭包自引用深度修复方案.md)

#### 问题描述

```php
<?php
$factorial = function($n) use (&$factorial) {
    return $n <= 1 ? 1 : $n * $factorial($n - 1);
};
echo $factorial(5);
```

**期望输出**: `120`  
**实际输出**: `error: InvalidCallback`

#### 根本原因

1. 闭包创建时，`$factorial` 变量还不存在
2. `use (&$factorial)` 捕获的是 null
3. `make_ref` 在闭包创建时固化了值
4. 后续赋值不会更新闭包内部的引用

#### 解决方案概要

**核心思路**：引入显式的引用槽（Reference Cell）机制

**关键步骤**:
1. **IR类型系统扩展** - 添加 `reference` 类型和引用槽指令
2. **静态分析** - 预扫描识别需要引用槽的变量
3. **闭包捕获修改** - 捕获引用槽指针而非值
4. **Runtime实现** - RefCell 数据结构 + 引用计数
5. **Codegen修改** - 生成引用槽指令

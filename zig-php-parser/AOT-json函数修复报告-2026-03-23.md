## 详细修复内容

### 1. json_last_error() 函数实现

**文件**: 
- `src/aot/runtime_lib_template.zig` (第 14642-14645 行)
- `src/aot/native_linker.zig` (函数映射表)
- `src/runtime/stdlib.zig` (dispatch 函数)

**功能**: 返回最后一次 JSON 编码/解码操作的错误代码

**实现要点**:
- 使用线程局部变量 `last_json_error_code` 存储错误状态
- 函数签名为 `pub fn php_json_last_error() Value`（不抛出错误）
- 标记为 `may_raise = false`，生成不带 `try` 的调用
- 不需要 allocator 参数

**错误代码**:
```zig
const json_error_none: i32 = 0;
const json_error_depth: i32 = 1;
const json_error_syntax: i32 = 4;
```

**测试结果**:
```php
$valid = '{"name":"test"}';
json_decode($valid);
echo json_last_error();  // 输出: 0

$invalid = '{"bad": json}';
json_decode($invalid);
echo json_last_error();  // 输出: 4 (语法错误)
echo json_last_error_msg();  // 输出: "Syntax error"
```

## 技术要点

### 1. 函数签名设计

**错误**: 最初使用 `pub fn php_json_last_error() !Value`
```zig
// ❌ 错误：返回错误联合类型
pub fn php_json_last_error() !Value {
    return Value.initInt(last_json_error_code);
}
```

**问题**: 在 native_linker 中标记为 `may_raise = false`，生成的代码不使用 `try`，导致类型不匹配。

**修复**: 改为直接返回 `Value`
```zig
// ✅ 正确：直接返回 Value
pub fn php_json_last_error() Value {
    return Value.initInt(last_json_error_code);
}
```

### 2. 线程局部存储

使用 `threadlocal` 关键字确保每个线程有独立的错误状态：
```zig
threadlocal var last_json_error_code: i32 = json_error_none;
```

### 3. 错误状态更新

在 `php_json_decode` 函数中更新错误状态：
```zig
pub fn php_json_decode(args: []const Value, allocator: Allocator) !Value {
    if (!json.isString()) {
        last_json_error_code = json_error_syntax;  // 设置错误码
        return Value.initNull();
    }
    // ... 解析逻辑
    last_json_error_code = json_error_none;  // 成功时重置
}
```

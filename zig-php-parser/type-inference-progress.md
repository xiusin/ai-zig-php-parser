# PHP AOT 编译器 - 类型推断系统开发进度报告

## 📅 日期：2026-02-13

## 🎯 目标
实现完整的类型推断系统，通过类型特化优化性能，目标：<3x 慢于 PHP。

## ✅ 已完成

### 1. 约束求解型类型推断系统（100%）
- **TypeConstraintSolver**：双向约束求解器
  - 4 种约束类型：concrete, equality, binary_op, phi
  - 双向传播：forward + backward
  - O(n) 复杂度，2 次迭代收敛
  - 100% 类型覆盖率

- **TypeInferencePass**：类型推断 Pass
  - 从 IR 指令收集约束
  - 调用 solver 求解
  - 返回完整的类型推断结果

### 2. 类型特化优化（部分完成）
- **Cast 穿透**：消除冗余的 i64 → php_value cast
  - 比较操作：✅ 完成
  - 算术操作：❌ 禁用（导致类型不匹配）

- **TypeSpecializationPass**：类型特化 Pass
  - 识别可优化的 cast
  - 绕过不必要的类型转换
  - 统计优化效果

### 3. 代码生成时类型推断（100%）
- **时机**：在 `generateFunction` 时重新推断
- **原因**：循环展开等优化会改变寄存器 ID
- **效果**：103 个类型成功推断（bench_simple_loop）

### 4. 架构设计（100%）
```
Optimizer (优化 IR)
    ↓ 循环展开/内联等
IR (寄存器 ID 变化)
    ↓ 传递到
NativeLinker.generateFunction
    ↓ 重新类型推断
TypeInferencePass (103 types)
    ↓ 覆盖寄存器类型（暂时禁用）
all_registers
    ↓ 代码生成
Zig 代码
```

## 🔴 当前问题

### 问题 1：类型覆盖导致类型不匹配
**现象**：
- 类型推断成功：reg_120 推断为 i64
- 类型覆盖成功：all_registers[120] = i64
- 寄存器声明：`var reg_120: i64 = 0;`
- 代码生成：`reg_120 = try runtime.php_add(...);`  // 返回 Value
- **结果**：编译错误 - expected i64, found Value

**根因**：
代码生成时没有根据推断类型选择正确的操作。

### 问题 2：类型特化代码生成缺失
**需要实现**：
在 `generateInstruction` 中根据操作数类型选择操作：

| 操作数类型 | 操作 | 生成代码 |
|-----------|------|---------|
| i64 + i64 | add | `result = lhs + rhs;` |
| Value + Value | add | `result = try php_add(lhs, rhs);` |
| i64 + Value | add | `result = try php_add(Value.initInt(lhs), rhs);` |

## 🎯 下一步计划

### 阶段 1：类型特化代码生成（P0）
**目标**：根据推断类型生成特化代码

**实施步骤**：
1. 在 `generateInstruction` 中获取操作数的推断类型
2. 对 add/sub/mul/div/mod 操作：
   - 如果两个操作数都是 i64 → 生成原生算术
   - 否则 → 生成 php_xxx 调用
3. 对比较操作（lt/le/gt/ge/eq/ne）：
   - 如果两个操作数都是 i64 → 生成原生比较
   - 否则 → 生成 php_xxx 调用

**预期效果**：
- bench_empty_loop：61ms → <20ms（3-4x 提升）

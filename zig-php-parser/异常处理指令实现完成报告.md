### 2. 代码生成器实现

在 `src/aot/native_linker.zig` 的 `generateInstructionSimple` 方法中添加了异常处理指令的代码生成：

```zig
// ============ 异常处理指令 ============
.try_begin => {
    // try_begin: 开始try块
    try writer.writeAll("    // Try block begin\n");
    try writer.writeAll("    {\n");
},
.try_end => {
    // try_end: 结束try块
    try writer.writeAll("    } // Try block end\n");
},
.catch_ => |op| {
    // catch: 捕获异常
    if (op.exception_type) |exc_type| {
        try writer.print("    // Catch block for exception type: {s}\n", .{exc_type});
    } else {
        try writer.writeAll("    // Catch block for all exceptions\n");
    }
    
    // 获取当前异常并存储到结果寄存器
    if (inst.result) |reg| {
        try writer.print("    reg_{d} = runtime.getCurrentException() orelse runtime.Value.initNull();\n", .{reg.id});
    }
},
.get_exception => {
    // get_exception: 获取当前异常
    if (inst.result) |reg| {
        try writer.print("    reg_{d} = runtime.getCurrentException() orelse runtime.Value.initNull();\n", .{reg.id});
    }
},
.clear_exception => {
    // clear_exception: 清除当前异常
    try writer.writeAll("    runtime.clearException();\n");
},
```

### 3. 运行时库支持

在 `src/aot/runtime_lib_template.zig` 中添加了异常处理的运行时函数：

```zig
// ============================================================================
// 异常处理
// ============================================================================

/// 当前异常（全局状态）
var current_exception: ?Value = null;

/// 设置当前异常
pub fn setException(exception: Value) void {
    current_exception = exception;
}

/// 获取当前异常
pub fn getCurrentException() ?Value {
    return current_exception;
}

/// 清除当前异常
pub fn clearException() void {
    current_exception = null;
}

/// 抛出异常
pub fn throwException(message: []const u8, allocator: Allocator) !Value {
    const msg_str = try PHPString.init(allocator, message);
    const exception = Value.initString(msg_str);
    setException(exception);
    return exception;
}

/// 检查是否有异常
pub fn hasException() bool {
    return current_exception != null;
}
```

## 设计说明

### Finally 块的实现

Finally 块不需要单独的 IR 指令，而是通过控制流（基本块）来实现：

1. IR 生成器在 `generateTryStmt` 中创建单独的 finally 基本块
2. Try 块和 catch 块都会跳转到 finally 块
3. Finally 块在执行完毕后跳转到退出块

这种设计符合 Zig 的控制流模型，并且与 PHP 的 finally 语义一致。

### 异常状态管理

当前实现使用全局变量 `current_exception` 来存储异常状态。这是一个简化的实现，适用于单线程 AOT 编译的程序。

在真实的 PHP 实现中，异常应该是线程局部的（thread-local），但对于 AOT 编译的单线程程序来说，全局变量已经足够。

## 限制和未来改进

### 当前限制

1. **Try-Catch 语法解析问题**：当前 IR 生成器在处理 try-catch 语句时存在 AST 节点数据结构不匹配的问题，需要修复。

2. **简化的异常模型**：当前实现使用全局变量存储异常，不支持多线程。

3. **异常类型检查**：当前实现不支持按异常类型进行匹配（如 `catch (SpecificException $e)`）。

### 未来改进方向

1. **修复 IR 生成器**：解决 try-catch 语句的 AST 节点解析问题。

2. **线程安全**：如果需要支持多线程，应该使用线程局部存储（TLS）来管理异常状态。

3. **异常类型系统**：实现完整的异常类型检查和匹配机制。

4. **栈展开**：实现更完整的异常栈展开机制，包括资源清理和 finally 块的正确执行。

5. **异常链**：支持异常链（exception chaining），即一个异常可以包含另一个异常作为原因。

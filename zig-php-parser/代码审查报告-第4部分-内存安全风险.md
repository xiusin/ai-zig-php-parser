## 第四阶段：内存安全风险矩阵

### 风险等级定义
- **严重**：可能导致崩溃、数据损坏或安全漏洞
- **高**：可能导致内存泄漏或性能问题
- **中**：可能导致不确定行为
- **低**：代码质量问题，不影响功能

## 关键风险详细说明

### 1. vm.zig GC UAF 风险（严重）

**问题描述**：
```zig
// 行 2026-2028
// 简化实现：假设对象会在下次访问时重置标记
```

**风险分析**：
- 未实际遍历对象图进行标记
- 可能导致活对象被错误回收
- 回收后的内存可能被重新分配
- 访问已回收对象导致 UAF

**CWE 编号**：CWE-416 (Use After Free)

**修复方案**：
```zig
/// 标记阶段：完整的对象图遍历
/// @pre roots 必须包含所有根对象
/// @post 所有可达对象的 marked 字段为 true
/// @safety-check 使用 @refCheck 验证引用有效性
fn markPhase(self: *BytecodeVM) !void {
    // 使用 complete_gc.zig 的实现
    var worklist = std.ArrayList(*GCObject).init(self.allocator);
    defer worklist.deinit();
    
    // 1. 从根集合开始
    for (self.roots.items) |root| {
        try self.markValue(root, &worklist);
    }
    
    // 2. 遍历工作列表
    while (worklist.popOrNull()) |obj| {
        // 验证对象有效性
        std.debug.assert(obj.magic_number == 0xDEADBEEF);
        try self.scanObject(obj, &worklist);
    }
}
```

### 2. vm.zig 双重释放风险（严重）

**问题描述**：
```zig
// free_strings 和 free_arrays 列表缺少防护
if (self.free_strings.items.len > 0) {
    const str = self.free_strings.items[self.free_strings.items.len - 1];
    // 如果 str 已被释放，这里会导致双重释放
}
```

**风险分析**：
- 空闲列表中的对象可能被多次释放
- 缺少 magic number 验证
- 可能导致堆损坏

**CWE 编号**：CWE-415 (Double Free)

**修复方案**：
```zig
pub const String = struct {
    data: []u8,
    ref_count: u32,
    marked: bool,
    magic_number: u64 = 0xDEADBEEF, // 添加魔数
    
    pub fn release(self: *String, allocator: std.mem.Allocator) void {
        // 验证魔数
        std.debug.assert(self.magic_number == 0xDEADBEEF);
        
        self.ref_count -= 1;
        if (self.ref_count == 0) {
            allocator.free(self.data);
            self.magic_number = 0xDEADDEAD; // 标记为已释放
            allocator.destroy(self);
        }
    }
};

// 从空闲列表获取时验证
if (self.free_strings.items.len > 0) {
    const str = self.free_strings.items[self.free_strings.items.len - 1];
    std.debug.assert(str.magic_number == 0xDEADDEAD); // 验证已释放
    str.magic_number = 0xDEADBEEF; // 重新激活
    // ...
}
```

### 3. hotspot_detector.zig 数据竞争风险（中）

**问题描述**：
```zig
// 哈希表结构修改需要锁保护
self.mutex.lock();
const entry = try self.execution_counts.getOrPut(func_name);
self.mutex.unlock();

// 但原子操作在锁外
_ = entry.value_ptr.fetchAdd(1, .monotonic);
```

**风险分析**：
- 哈希表修改在锁内，但值修改在锁外
- 可能导致计数不准确（虽然使用原子操作）
- 理论上安全，但代码不够清晰

**修复方案**：
```zig
/// @thread-safety GUARDED_BY(mutex)
/// @concurrency-model Actor-Based
pub fn recordExecution(self: *HotspotDetector, func_name: []const u8) !void {
    if (!self.config.enabled) return;
    
    // 增加总调用计数（无锁）
    _ = self.stats.total_function_calls.fetchAdd(1, .monotonic);
    
    // 获取或创建计数器（需要锁）
    self.mutex.lock();
    defer self.mutex.unlock(); // 确保释放
    
    const entry = try self.execution_counts.getOrPut(func_name);
    if (!entry.found_existing) {
        const name_copy = try self.allocator.dupe(u8, func_name);
        entry.key_ptr.* = name_copy;
        entry.value_ptr.* = std.atomic.Value(u32).init(0);
    }
    
    // 原子增加计数（在锁内更安全）
    _ = entry.value_ptr.fetchAdd(1, .monotonic);
}
```

## 内存安全检查工具链

### 推荐工具
1. **Valgrind** - 内存错误检测
   ```bash
   valgrind --leak-check=full --show-leak-kinds=all ./zig-php
   ```

2. **AddressSanitizer** - 编译时插桩
   ```bash
   zig build -Doptimize=Debug -fsanitize=address
   ```

3. **std.testing.allocator** - 测试时泄漏检测
   ```zig
   test "no memory leaks" {
       var vm = try BytecodeVM.init(std.testing.allocator);
       defer vm.deinit();
       // 测试代码
   }
   ```

4. **LoggingAllocator** - 跟踪分配
   ```zig
   var logging_allocator = std.heap.LoggingAllocator(.info){
       .parent_allocator = std.heap.page_allocator,
   };
   ```

### build.zig 配置
```zig
const exe = b.addExecutable(.{
    .name = "zig-php",
    .root_source_file = b.path("src/main.zig"),
    .target = target,
    .optimize = optimize,
});

// 启用边界检查
exe.setBuildMode(.Debug);
exe.setExecCmd(&[_][]const u8{
    "valgrind",
    "--leak-check=full",
});

// 启用 AddressSanitizer
if (optimize == .Debug) {
    exe.sanitize_thread = true;
    exe.sanitize_address = true;
}
```

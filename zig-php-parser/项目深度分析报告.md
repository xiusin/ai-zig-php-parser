## 二、AOT和解释器模式的关键差异

### 2.1 执行模式对比

| 维度 | AOT模式 | 解释器模式（VM） | JIT模式 |
|------|---------|------------------|---------|
| **编译时机** | 编译时预编译 | 运行时解释执行 | 运行时热点编译 |
| **输出产物** | 原生可执行文件 | 无（直接解释） | 机器码缓存 |
| **启动速度** | 快（直接运行） | 慢（需解释） | 中等（首次编译） |
| **运行时开销** | 无 | 高 | 低 |
| **内存管理** | 引用计数 | GC | GC |
| **支持特性** | 基础运算、控制流 | 全部 | 大部分 |
| **代码优化** | LLVM完整优化 | 解释执行 | 部分优化 |
| **适用场景** | 生产部署、CLI工具 | 开发调试、脚本 | 长期运行服务 |

### 2.2 核心架构差异

**AOT模式架构：**
```
PHP源文件 → AST → 类型推断 → IR → 优化 → LLVM → 原生代码 → 可执行文件
                                                                    ↓
                                                           AOT运行时库（runtime_lib_template.zig）
```

**解释器模式架构：**
```
PHP源文件 → AST → 树遍历解释器 → VM指令执行
                                    ↓
                              运行时库（builtin_*.zig, vm.zig）
```

**JIT模式架构：**
```
PHP源文件 → 热点检测 → x64汇编 → 机器码缓存 → 直接执行
```

**AOT编译器入口：** `src/aot/compiler.zig`

**AOT实现 (runtime_lib_template.zig:740):**
```zig
pub fn php_add(lhs: Value, rhs: Value) !Value {
    if (lhs.isInt() and rhs.isInt()) {
        const a = lhs.asInt();
        const b = rhs.asInt();
        const result = @addWithOverflow(a, b);
        if (result[1] != 0 or result[0] < Value.INT48_MIN or result[0] > Value.INT48_MAX) {
            return Value.initFloat(@as(f64, @floatFromInt(a)) + @as(f64, @floatFromInt(b)));
        }
        return Value.initInt(result[0]);
    }
    const a = lhs.toFloat();
    const b = rhs.toFloat();
    return Value.initFloat(a + b);
}
```

**FastVM实现 (fast_value.zig:344):**
```zig
pub fn add(a: FastValue, b: FastValue) FastValue {
    if (a.isInt() and b.isInt()) {
        const ai = a.asInt();
        const bi = b.asInt();
        const result = @addWithOverflow(ai, bi);
        if (result[1] != 0 or !FastValue.fitsIn48Bits(result[0])) {
            return addFloat(FastValue.initFloat(a.toFloat()), FastValue.initFloat(b.toFloat()));
        }
        return FastValue.initInt(result[0]);
    }
    return addFloat(FastValue.initFloat(a.toFloat()), FastValue.initFloat(b.toFloat()));
}
```

```zig
pub fn spawn(self: *CoroutineManager, callback: Value, args: []const Value) !u64 {
    const coroutine_id = self.next_id;
    self.next_id += 1;

    const coroutine = try self.allocator.create(Coroutine);
    errdefer self.allocator.destroy(coroutine);

    coroutine.* = .{
        .id = coroutine_id,
        .callback = callback,
        .args = try self.allocator.dupe(Value, args),
        .state = .ready,
        .stack_size = self.default_stack_size,
        .priority = .normal,
        .parent_id = self.current_id,
        .wait_group = null,
        .channel = null,
    };

    try self.ready_queue.push(coroutine);
    return coroutine_id;
}
```

### 5.2 违反SOLID原则

#### 违规3：Value类型职责过多

**位置：** `src/aot/runtime_lib_template.zig` 和 `src/runtime/types.zig`

**违反原则：** SRP（单一职责原则）、ISP（接口隔离原则）

**问题代码 (runtime_lib_template.zig):**

```zig
pub const Value = struct {
    data: u64,  // NaN boxing编码

    pub fn isFloat(self: Value) bool { ... }
    pub fn isString(self: Value) bool { ... }
    pub fn isBool(self: Value) bool { ... }

    pub fn asFloat(self: Value) f64 { ... }

    pub fn toInt(self: Value) i64 { ... }
    pub fn toFloat(self: Value) f64 { ... }

    pub fn php_mul(self: Value, other: Value) !Value { ... }
    pub fn php_div(self: Value, other: Value) !Value { ... }
    pub fn php_mod(self: Value, other: Value) !Value { ... }
    pub fn php_pow(self: Value, exp: Value) !Value { ... }
```

**违反的SOLID原则：**
- **S (单一职责)**：Value类型同时负责数据存储、类型检查、类型转换、运算符实现、字符串操作
- **I (接口隔离)**：用户需要依赖大量不需要的方法
- **D (依赖倒置)**：高级模块（VM）依赖低级模块（Value）的具体实现

**位置：** `src/aot/codegen.zig` 与 `src/aot/runtime_lib_template.zig`

**违反原则：** DIP（依赖倒置原则）、LoD（迪米特法则）

**问题代码 (codegen.zig):**

**问题：**

### 5.3 违反内存安全原则

#### 违规5：手动内存管理与GC混用

**位置：** `src/aot/runtime_lib_template.zig` vs `src/runtime/gc.zig`

**违反原则：** 内存安全一致性、最小意外原则

**AOT使用引用计数（手动管理）:**

```zig
pub const PHPString = struct {
    data: []u8,
    length: usize,
    ref_count: usize,
    is_static: bool,

    pub fn retain(self: *PHPString) void {
        if (!self.is_static) {
            self.ref_count += 1;
        }
    }

    pub fn release(self: *PHPString, allocator: Allocator) void {
        if (self.is_static) return;
        if (self.ref_count == 0) return;
        self.ref_count -= 1;
        if (self.ref_count == 0) {
            self.deinit(allocator);
        }
    }
};
```

**VM使用GC（自动管理）:**

```zig
const gc = @import("gc.zig");

pub fn allocateValue(self: *GC, comptime T: type) !*T {
    const ptr = try self.allocator.create(T);
    // GC自动管理内存，无需手动释放
    return ptr;
}
```

**问题：**
1. 两种模式使用完全不同的内存管理策略
2. 增加开发者认知负担
3. 容易引入内存泄漏或悬挂指针
4. 难以保证代码正确性

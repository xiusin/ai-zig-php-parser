## 一、编译失败 (2个)

### 1. test_018_named_args.php — 命名参数调用
- **错误**: `expected 4 argument(s), found 3`
- **生成代码**: `php_object_call_named_args(reg_2, reg_12, reg_3)` 缺少 allocator
- **根因**: `php_object_call_named_args` 未在 native_linker 函数表中注册，走通用路径时参数填充不正确
- **修复方案**: 
  1. 在 `native_linker.zig` 的 builtin 函数表中注册 `php_object_call_named_args`
  2. 或在特殊处理分支中添加参数填充逻辑
  3. 需要先确认 `php_object_call_named_args` 在 `runtime_lib_template.zig` 中的签名

### 2. test_069_arguments.php — 同上，命名参数调用
- **错误**: 同 test_018
- **修复方案**: 同上

## 二、运行失败 — ZIG_ERROR (rc=1，Zig内部错误未捕获，4个)

### 3. test_039_variable_funcs.php — UnknownFunction
- **错误**: `error: UnknownFunction` (rc=1)
- **根因**: 可变函数调用 `$func()` 在 AOT 中找不到对应的函数
- **修复方案**: 检查 `php_invoke_callable` 中的函数查找逻辑，确保用户定义函数和内置函数都能被找到。可能需要在 AOT 生成的代码中注册所有用户函数到 `user_function_registry`

### 4. test_055_static_late.php — ClassNotFound
- **错误**: `error: ClassNotFound` (rc=1)
- **根因**: 后期静态绑定(LSB) `static::class` 在闭包中调用时找不到类
- **修复方案**: 
  1. 检查 `getCurrentCalledClass()` 在 AOT 模式下是否正确设置
  2. 在 `php_invoke_callable` 调用闭包前，确保 `ClassContext` 被正确传递
  3. 关键文件: `src/aot/runtime_lib_template.zig` 中的 `php_get_called_class_name()` 和 `setCurrentCalledClass()`

### 5. test_153_closure_binding.php — ClassNotFound
- **错误**: `error: ClassNotFound` (rc=1)
- **根因**: `Closure::bind()` 或 `Closure::bindTo()` 中指定的类名找不到
- **修复方案**: 检查 `php_closure_bind` 实现中的类名解析逻辑，确保能解析 `self`、`static`、`parent` 等特殊类名

### 6. test_220_validator.php — InvalidCallback
- **错误**: `error: InvalidCallback` (rc=1)
- **根因**: 回调函数格式不被识别（可能是 `[$this, 'method']` 格式）
- **修复方案**: 虽然 `php_call_user_func` 中的 `InvalidCallback` 已改为返回 false，但 `php_invoke_callable` 中可能还有未修复的路径。检查 `php_invoke_callable` 中所有 `return error.*` 的位置

## 四、运行失败 — PARSE_ERROR (rc=255，解析器语法问题，4个)

### 16. test_028_hooks.php — PHP 8.4 属性钩子
- **错误**: `Parse error: unexpected "(", expecting "{"`
- **根因**: PHP 8.4 的属性钩子语法 `public string $name { get => ...; set => ...; }` 未被解析器支持
- **修复方案**: 在 `src/compiler/parser.zig` 中添加属性钩子语法解析。这是 PHP 8.4 新特性，需要在属性声明后识别 `{` 开始的钩子块

### 17. test_052_const_expr2.php — 常量表达式
- **错误**: `Parse error: unexpected token, expecting ";"`
- **根因**: 复杂常量表达式（如 `const X = [1, 2, ...range(3,5)]`）未被解析器支持
- **修复方案**: 在解析器的常量表达式解析中支持数组展开运算符 `...`

### 18. test_130_spread_method.php — 方法调用中的展开运算符
- **错误**: `Parse error: unexpected variable "$numbers", expecting ")"`
- **根因**: `$obj->method(...$args)` 中的展开运算符未被解析器支持
- **修复方案**: 在解析器的函数调用参数解析中支持 `...` 展开运算符

### 19. test_147_logical_ops.php — 逻辑运算符语法
- **错误**: `Parse error: unexpected token, expecting ")"`
- **根因**: 可能是 `match` 表达式中的复杂逻辑运算符组合
- **修复方案**: 需要查看具体脚本内容确认是哪种语法不支持

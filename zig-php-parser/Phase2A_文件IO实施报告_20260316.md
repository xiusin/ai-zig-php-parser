### 文件句柄实现

**关键设计**:
- 使用真实`std.fs.File`指针作为句柄
- 通过`@intFromPtr`和`@ptrFromInt`转换
- 需要手动管理内存（fclose时释放）

**潜在问题**:
- 内存泄漏：如果用户忘记fclose
- 野指针：如果用户多次fclose
- 类型安全：没有验证指针是否真的是File*

## 🎓 技术洞察

### 1. 签名设计的权衡

**数组签名** `args: []const Value`:
- ✅ 灵活：支持可变参数
- ✅ 统一：所有函数相同签名
- ❌ 复杂：需要特殊列表
- ❌ 性能：额外的数组包装

**简单签名** `arg1: Value, arg2: Value`:
- ✅ 简单：直接参数传递
- ✅ 性能：无额外开销
- ❌ 固定：参数数量固定
- ❌ 重复：每个函数不同签名

**选择**: 对于参数固定的函数，使用简单签名

### 2. 资源管理的挑战

**PHP的资源类型**:
- 文件句柄
- 数据库连接
- 网络socket
- 进程句柄

**Zig的实现**:
- 使用指针转整数
- 缺少类型安全
- 需要手动管理生命周期

**改进方向**:
- 实现资源注册表
- 自动垃圾回收
- 类型标记和验证

### 3. toString的陷阱

**常见错误**:
```zig
const str = try value.toString(allocator);
defer allocator.free(str);  // ❌ 错误！
```

**正确做法**:
```zig
const str = try value.toString(allocator);
defer str.release(allocator);  // ✅ 正确
// 使用 str.data 访问字符串
```

**原因**: toString返回PHPString*，不是[]const u8

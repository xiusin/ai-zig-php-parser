# AOT编译器已知问题

## 严重问题

### 1. 嵌套try-catch中的变量生命周期问题 🔴

**影响**: 连续的嵌套try-catch可能导致变量状态损坏

**复现条件**:
```php
$arr = getArray();
$results[] = "Got:" . $arr['value'];  // 正常

try {
    throwE1();
} catch (E1 $e) {
    $results[] = "E1";  // 正常
}

try {
    functionThatThrows($arr);  // 传递数组
} catch (E2 $e) {
    $results[] = "E2";  // 正常
}

echo implode("|", $results);  // 崩溃：StringTooLarge 或 Segmentation fault
```

**根本原因**: 异常处理后，某些变量（特别是数组）的内部状态被破坏

**症状**:
- `error: StringTooLarge` - 字符串长度异常
- `Segmentation fault` - 访问无效内存
- 输出缺失或顺序错误

**临时解决方案**:
1. 避免在连续的try-catch之间共享复杂变量
2. 在每个try-catch后重新获取数据
3. 使用单层try-catch而不是嵌套

**示例 - 避免问题**:
```php
// ❌ 有问题的代码
$arr = getArray();
try { throwE1(); } catch (E1 $e) { }
try { func($arr); } catch (E2 $e) { }  // $arr可能已损坏

// ✅ 安全的代码
try { 
    throwE1(); 
} catch (E1 $e) { }

$arr = getArray();  // 重新获取
try { 
    func($arr); 
} catch (E2 $e) { }
```

**状态**: 🔄 正在调查
- 需要深入分析异常处理的IR生成和代码生成
- 可能涉及寄存器分配和内存管理
- 预计需要重构异常处理机制
